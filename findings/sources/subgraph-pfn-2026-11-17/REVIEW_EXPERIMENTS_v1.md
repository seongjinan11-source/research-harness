# SPFN01 실험·기준선·통계 검토 — PLAN_v1

2026-11-17. **판정: 수정 후 진행.** 같은 관측 context를 두고 작은 decoder 예산에서 희소 라벨을 개별 보존하는 가설을 검증할 수 있다. `top`의 입력·count·mass 규칙, 합성 분모와 go/no-go 조건, real 고정 draw를 구현 전 하나의 protocol로 잠가야 한다. 이 수정은 후보를 추가하거나 평가 규모를 늘리지 않는다. 검토는 계획/기존 로컬 원자료를 읽기만 했고, 새 bank·훈련·GPU·실험 소스 작업은 하지 않았다.

## 1. 비교가 바꾸는 한 가지와 실제 예산

`tail`과 `proportional`의 차이는 **반드시 allocation만** 남긴다. 같은 graph, complete X, context IDs/labels, query IDs, self-loop/convolution/PPR truncation, feature standardization, per-class group partition, pair channels, decoder, loss, initialization, physical task schedule을 공유한다. `B = Σ_c q_c^tail`을 실험 전에 context counts에서 계산하고 proportional은 같은 B를 사용한다. `q_c^tail=n_c` for `n_c≤4`, `min(2,n_c)` otherwise; proportional은 클래스당 한 슬롯, `q_c≤n_c` 제약에서 남은 슬롯을 n_c 비례 정수 배분한다. 남은 몫의 재분배와 동률 순서를 고정한다. 가능한 동률 해결은 클래스 명칭 대신 그 클래스의 최소 stable context ID를 쓰는 것이다. 같은 규칙을 inverse class rename과 함께 시험한다. `full`은 모든 singleton의 예산 밖 reference이며 성능의 이론적 상한은 아니다.

`top`은 tail과 **각 query, 각 class마다 같은 q_c**를 써야 raw retrieval과 그룹 압축의 비교가 된다. 동일한 전체 C 중 클래스별 실제 finite PPR의 내림차순으로 고르고 동률은 stable node ID로 고정한다. Tail 클래스에선 q_c=n_c이므로 전부 포함한다. 어떤 클래스에 reachable anchors가 적어도 zero-mass anchor로 quota를 채운다. 그래야 완전히 disconnected인 query에서도 `top`만 용량·fallback이 다른 비교가 되지 않는다. 같은 전체 H를 읽고, singleton local/global feature는 선택한 H_i, mass/reach는 실제 singleton diffusion 값을 그대로 쓴다. `n_c/q_c`는 token count proxy와 그것으로 정해지는 pooling log-count에만 넣는다. **실제 m까지 이 count로 다시 가중하지 않는다.** 그래야 집계된 PPR의 우위를 비교한다는 이유로 top의 PPR 토큰에 다른 aggregation을 몰래 적용하지 않는다. 이 proxy는 정수가 아닐 수 있으므로 float로 보존한다. 클래스 총 count는 공통 explicit side-channel로 모든 learned arms에 넣거나 모두 생략한다; top만 n_c 정보를 잃게 하면 안 된다. Count를 보존한 top이 전체 anchor signal을 복원한다는 뜻은 아니다.

이 비교에서 같은 것은 **사용할 수 있는 관측 정보와 scoring 시 token 수**다. `top`은 같은 C 모두를 스캔하며 query마다 다르게 고를 수 있고, `tail`은 모든 C의 통계를 공유 prototype에 담는다. 일치하는 것은 raw evidence 접근이며 출력 representation은 의도적으로 다르다. 전처리 때 실제 읽는 모든 C, grouped preprocessing workspace, per-query retrieval, scoring tokens, query chunk당 peak activations를 각각 보고한다. Top은 singleton `F(B_i H)=F(B_i)H_i`를 이용해 N×|C| scalar seeds만 diffuse하면 되고, **full도 같은 singleton 최적화를 허용**한다. Full/Top에 불필요한 moment columns를 계산시켜 비교를 유리하게 만들지 않는다. Dense N×N은 필요 없다. Rule controls에도 동일 P/H와 observation interface를 준다.

고정 장치/dtype/threads/query chunk, 공통 warmup·동기화로 split 준비, projection/standardization, H 계산, grouping, diffusion/retrieval, neural scoring, peak memory를 분리 기록한다. 한 graph에서 여러 query에 공유한 전처리와 cold end-to-end wall을 구분한다. Stage별 work counts(E, C, G, Q, F, diffusion passes)도 남긴다. 같은 320 optimizer groups가 동일 FLOPs/wall을 뜻하지 않는다. Query count가 작은 accuracy panel은 그대로 두되 holdout/real의 larger scoring batch가 없으면 모든 query에 대한 throughput 주장도 하지 않는다. 사용자의 큰 graph·소수 context 동기는 유지하되, 이 결과의 범위는 실제 측정한 최대 graph 크기와 decoder budget까지다.

## 2. 합성 분모, gate, 기준선 규칙을 고정

- Final96을 **2 shape ×2 graph regime ×2 feature regime ×12 independent base graphs**로 확정한다. Matched48과 scale/budget holdout48. Heldout는 N/F와 head support가 함께 바뀌므로 단일 N scaling 효과가 아니라 사전 정의된 복합 shape/context-budget shift다. 독립 RNG stream으로 role/class selection, features/edges, context/query draw를 나누고 split별 seed ranges, actual N/K/F, true population counts, context counts, role, ordered Q/C, graph/feature regimes와 hashes를 저장한다. Context support skew와 true population imbalance는 가능한 범위에서 별도 draw한다. Sampling feasibility 조건이 양자를 묶으면 기록한다. Tail의 정의는 끝까지 observed count≤4이며 true class rarity로 읽지 않는다.
- 매 graph에 head와 tail이 적어도 하나씩 있게 하고, 각 class population이 `context_count+8`을 수용하도록 **by construction** 고정해 query를 정확히 8/class로 만든다. Anchor/query 집합은 비중복이고 role·query truths는 train CE와 평가 쪽에만 존재한다. 가장 작은 synthetic N160도 4 head×24 + tail4 +5×8=140의 인원 상한을 만족하므로 8/class를 고정할 수 있다. Class occupancy와 edge agreement가 생성 함수의 의도와 실제로 맞는지, 실제 homophily/feature regime 지원을 도출하고 score 기반 재추출 없이 기록한다. Final 구조 위반은 전체 재추출 또는 유리한 subset 선택으로 처리하지 않는다. Case completeness 실패를 gate undefined로 명시한다.
- 모델 4 arms ×3 seeds ×320 optimizer groups = **12 fits / 3,840 successful updates**를 유지하고 group당 graph/exposures, episode를 유일하게 쓰는지·재사용하는지, retry/skip, matched seed init/physical schedule의 범위를 lock한다. Dev12는 안정성/비용 및 고정 recipe 검증에서만 쓰며 final96은 사전 gate가 잠긴 뒤 평가한다. Heldout patch/통계 오류가 있다면 원출력 보존 하에 provenance를 남기고 처리한다. 점수를 본 뒤 N/F, role 편성, B, decoder, 규칙 또는 group capacity를 바꾸지 않는다.
- Primary는 graph별로 `tail recall = mean_{c:n_c≤4} TP_c/N_query,c`를 먼저 산출하고 **고정 3 seeds의 metrics**를 평균한 후 paired difference를 만든다. 예측 확률 seed ensemble이 아니다. 96 base graphs의 동일 가중 평균과 within-stratum graph bootstrap5000회, nominal two-sided97.5% CI를 고정한다. Bootstrap seed와 strata draw 순서도 protocol에 넣는다. Sample unit은 graph 하나이며 query/seed/classes를 독립 복제로 세지 않는다. Tail−proportional과 tail−top 양쪽 lower>0; full guard는 **같은 전체96**의 overall BAcc paired contrast, 동일 two-sided97.5% CI lower>−0.02로 먼저 잠그는 것을 권한다. Heldout48의 guard difference를 별도 기술할 수 있지만 결과를 보고 denominator를 바꾸지 않는다. 통과하더라도 모든 판정 CI가 하나의 동시 95% 구간이라는 주장은 피한다. CI는 고정 세 학습 seed와 제한된 synthetic generator 분포에 조건부다.
- 기술적 sanity floor를 숫자로 쓴다. 예: 같은96의 동일 tail-bAcc weighting에서 `tail mean ≥ max(balanced-PPR mean, centroid mean)`을 모두 요구하고 paired 점추정·CI도 보여 준다. 이는 기술적 비교선이며, floor 통과 자체가 두 rule보다 statistically superior함을 뜻하지 않는다. “incremental effect”는 사전 tail−top 및 tail−proportional gate로 해석하고 숨은 별도 판정을 남겨 두지 않는다. Balanced PPR은 `s_qc = Σ_{i∈C_c} m_qi / n_c`를 classes 간 normalize(모든 class mass 0이면 uniform). Centroid는 모든 labeled class centroid의 거리로 정하고 feature hop scales/거리·ties 및 NLL/Brier 산출용 확률 변환(예: 명시적인 고정 temperature)도 미리 정한다. Uniform prior는 알려진 vocabulary에 1/K이며 실제 query population prior가 아니다. 세 rule 모두 독립 training seeds로 복제할 필요가 없다.

Compression guard를 숫자로 쓰자면 holdout48에서 `mean_graph(C_full)/mean_graph(B_tail) ≥ 2`다. 위 설계에서 tail singleton 총 T≤16, head classes h≥1이면 C_full≥T+24h, B_tail≤T+2h여서 각 holdout graph의 비율은 ≥40/18≈2.22다. 따라서 **2×는 사실상 구성 검사**로, 구현에서 counting이 맞는지 확인한다. 이 통과만으로 latency, memory, error-rate superiority가 나온다고 말할 수 없다. 반면 quality guard를 동반하면 “사전 count 감소에서 full 대비 BAcc 비열등성”은 실제 결과가 된다.

## 3. 실제 패널: 가용성 확인과 고정 draw 권고

로컬 `ctxedit/data/planetoid_pyg/{Cora,CiteSeer,PubMed}/processed/data.pt` 세 파일을 CPU로 확인했다. Cora2708×1433과 CiteSeer3327×3703는 full graphs다. PubMed는 `factor_homophily_benchmark/bank/PubMed_r0_95.npz`의 `original_ids`를 고정해 parent19717×500 중 기존 induced2000을 사용 가능하다. 이전 mask나 projected features 대신 이 source의 전체 native values와 induced edges를 읽어야 한다. 해당 inherited ID-anchor SHA256은 `1bd550870a89d3a5c2c5ae857bbe7b6d798500a06ea7a599f6de753fa7402c06`이고 실제 induced class counts는 280/974/746이다. Cora와 CiteSeer 최소 class count는 각각180/264로, panel 전체를 샘플 universe로 정하면 head16과 class당 8 queries가 확실히 가능하다. 따라서 이 panel에서는 임의의 smaller cap이 필요하지 않다.

하나의 단순한 predeclared recipe를 추천한다. Graph별 5 seed draws; class 역할은 `t=floor(K/2)`개 tail을 true population count와 무관하게 seed로 고르고, 나머지는 head. 각 class에서 without replacement ordered draw를 하여 tail2/head16 context와 다음8 queries를 분리한다. Tail count와 query 진실은 샘플 설계/score용이며, predictor에는 context만 제공한다. 동일 graph 반복 사이의 node overlap은 허용하되 저장한다. 이 경우 분모는 다음과 같다.

| 개발 graph | K | Tail / head classes | Context C | Learned budget B | Queried nodes Q | Fixed draws |
|---|---:|---:|---:|---:|---:|---:|
| Cora full | 7 | 3 / 4 | 70 | 14 | 56 | 5 |
| CiteSeer full | 6 | 3 / 3 | 54 | 12 | 48 | 5 |
| PubMed induced2000 | 3 | 1 / 2 | 34 | 6 | 24 | 5 |

즉 15 episodes/3 reused graphs, 네 trained arms ×3 seeds ×15 = 180 main prediction records, 세 deterministic rules를 쓸 경우 45 reference records다. 이는 balanced class episode 설계이지 natural prevalence 추정이나 기존 official Planetoid test split 결과가 아니다. 해당 benchmark를 쓰려면 공용 pool split과 class capacity를 별도로 먼저 고정해야 한다. 이전 FP05 k4/class, 이전 k20/class benchmark와 수치를 직접 비교하지 않는다. K6/7 real에서 synthetic K≤5 및 graph 규모가 바뀌는 점도 원인으로 단정하지 말고 보고한다. Query나 3 fit seeds×5 draws를 15 independent graph로 취급하지 않고 per-graph paired draw mean/spread만 제시한다. Real 결과는 합성 gate 실패와 무관하게 준비/실행하되 새 population-transfer 근거로 사용하지 않는다.

권장 공통 real F=24: per-graph deterministic Rademacher projection(/√24, seed lock)을 complete native X에 적용하고 합성 arm과 같은 표준화를 사용한다. Native dimension/ID/edges/feature/projection/context/query hashes를 보존한다. Preprocessing은 transductive unlabeled X/G를 동일하게 이용하고 숨긴 labels를 쓰지 않는다. 외부 NodePFN이 준비됐다면 **동일 G/C/Q와 frozen original weights**의 별도 기술적 비교만 한다. Native representation·pretraining·context capacity가 다르면 명시하고, interface나 checkpoint가 없으면 가용성 이유를 기록한다. Archive에서 찾지 못한 ImbNodePFN 최종 체크포인트를 관련 predecessor로 대체해 “재현”했다고 하지 않는다. 이전 missing/observation-halo baseline의 숫자도 complete-feature 실험의 짝 비교로 옮기지 않는다.

사전 protocol이 위 정의들을 고정하면, 먼저 numerical/reference/serialization checks와 작은 resource preflight를 마친 다음 본래 12 fits와 96+15 episode 평가로 진행해도 된다. Group counts와 같은 raw evidence의 일치, target leakage, query chunk/ordering, standardization과 singleton/diffusion parity를 저장 arrays로 확인한다. 결과가 어느 gate를 놓쳤는지 기록하고, final을 보고 rule이나 token/exposure를 다시 설계해 이 후보를 구제하지 않는다.
