# 아이디어 점검 (2026-11-02)

> 미실행 가설: 같은 graph/feature/label 생성 family와 관측 예산에서, 관측값을 공개하기 전 prior predictive 평균으로 계산한 feature 관측의 Bayes 0-1 risk 감소를 이용해 학습 mask 배치를 생성한다. 기존 finite-bank reference-regret 재가중이나 mechanism crossing과 분리하며, 배포 때 mask를 선택하거나 숨은 값을 조회하지 않는다. 동일 PFN과 CE를 유지하고 random mask, 거리/coverage 규칙, 동일 생성 비용 대조와 비교한다. 정확도 관련 VOI와 log-loss 관련 conditional MI를 분리하며, 현재 Gaussian working model을 원 generator의 exact teacher로 가정하지 않는다. 새로운 성능·novelty 입증은 없다.

태그: eval-protocol, model-based-baseline, observation-mask, pretraining-data / 키워드: Bayes decision value, observation design, conditional information, mask prior, synthetic task generation, feature utility

## 1. 차별점을 정리해야 할 선행연구
같은 축을 이미 강점으로 내세운 방법 논문이에요. 기각 사유가 아니라, 무엇이 다른지 한 줄로 써둘 대상입니다.

- **Chronos-2** [pretraining-data] 실제 다변량 데이터 없이 synthetic multivariatizer만으로 다변량·covariate 능력을 얻었다. synthetic 데이터만으로 학습한 변형도 GIFT-Eval과 Chronos Benchmark II에서 본 모델에 거의 근접해, synthetic prior 설계의 효과를 보여준다.
- **CSBMInference** [model-based-baseline] Node labels와 latent feature centroids를 같은 추론 계산에서 갱신하는 직접적인 선행연구다. Feature–label 대응을 graph로 연결한다는 발상 자체의 novelty를 제한한다.
- **CSBMInference** [model-based-baseline] GNN보다 높은 정확도를 얻는 model-based reference와 공개 구현을 제시하며, Bethe free entropy를 이용한 parameter estimation을 다룬다.
- **GraphPFN** [pretraining-data] Graph prior가 구조(multi-level SBM + preferential attachment)와 attribute(MLP·GNN neuron 혼합 SCM)를 분리해 설계되어 있고, 그래프 의존 정도를 mixing 확률로 조절할 수 있다. 부록 분석에서 synthetic graph의 평균 차수·clustering·power-law 적합도 분포가 실제 GraphLand 그래프 통계를 대체로 덮는다.
- **GSPN** [observation-mask] 숫자 대치나 여러 completion forward 없이 모델 내 partial-evidence 추론을 제공한다.
- **MaM** [observation-mask] Marginal과 conditional을 연결하는 self-consistency를 명시한다.
- **MCSSL** [observation-mask] 정보 증가에 따른 예측 갱신을 허용하면서 평균의 일관성을 제약한다.
- **Moirai** [pretraining-data] LOTSA, 학습 라이브러리 uni2ts, 모델 가중치를 모두 공개했다. LOTSA 대신 Monash와 GluonTS만으로 학습하면 in-distribution인 Monash에서도 정규화 MAE가 0.655에서 0.809로 나빠져, 데이터 다양성이 cross-domain 학습에 중요하다는 점을 보였다.
- **MOMENT** [pretraining-data] 모델 가중치, 사전학습 데이터(Time-series Pile), 코드를 모두 공개했다. 당시 TSFM 다수가 데이터나 가중치를 닫아 두었던 상황에서 재현과 후속 분석의 기반이 되었다.
- **NodePFN** [pretraining-data] 합성 그래프 수를 늘릴수록 성능이 오르는 prior-scale 분석과, ER·cSBM·BA 구성을 바꾼 prior ablation을 함께 제시해 어떤 prior 성분이 도움이 되는지 일부 보여준다.
- **PEMix** [observation-mask] Clustered missingness의 전파 경계 병목을 분석하고, 관측값 전파에 의존하지 않는 구조 조건부 feature distribution을 제시한다.
- **PEMix** [observation-mask] Fully missing node에서도 PE-conditioned mixture responsibility가 남아 노드별 대치를 구분할 수 있다.
- **PFNSeparability** [pretraining-data] Feature law와 conditional label law의 의존성을 prior 설계의 명시적 선택으로 다룬다.
- **SSGP** [model-based-baseline] 소수 라벨에서 evidence 기반 선택을 cross-validation과 비교한다.
- **StructuralMissingPFN** [observation-mask] Mask를 포함한 불완전 입력에서 직접 예측하며 explicit posterior sampling과 분류 경로를 구분한다.
- **Sundial** [pretraining-data] 약 1조 시점 규모의 TimeBench로 규모를 키우는 효과를 보였다. Large는 Small보다 수렴 training loss가 15.38% 낮았고, TSLib에서도 모델이 클수록 일관되게 좋아졌다.
- **TabImpute** [observation-mask] 새 table에서 fitting 없이 대치하며 row-column 정보를 cell 단위로 공유한다.
- **TabImpute** [observation-mask] Section 3의 architecture는 원래 TabPFN의 query 사이 attention 제한을 제거한다. Missing-entry query가 공유 잠재 구조를 통해 의존할 수 있다는 이유이며, 우리 graph PFN의 성능 개선을 입증한 결과는 아니다.
- **Time-MoE** [pretraining-data] 309B 시점 규모의 Time-300B와 정제 pipeline을 공개했다. 결측 구간은 평균으로 채우지 않고 잘라내고, 1·2차 차분 비율로 비정상 window를 걸러낸다. 학습 코드와 데이터가 모두 공개되어 있어서, TimeSqueeze처럼 backbone과 데이터를 그대로 두고 tokenizer만 바꾸는 통제 실험의 기반으로 쓰이고 있다.
- **TimesFM** [pretraining-data] synthetic 데이터를 빼면 실제 데이터에 드문 granularity(quarterly, yearly, 10분 등)와 15분 ETT에서 성능이 떨어진다는 ablation을 보여, 실제 corpus의 빈 곳을 synthetic prior로 메우는 효과를 실증했다.
- **TimesFM** [pretraining-data] 17M, 70M, 200M으로 키울수록 Monash 오차가 단조 감소해 시계열에서도 규모를 키우는 효과가 있음을 초기에 보였다.
- **Wander** [pretraining-data] Synthetic prior가 NodePFN식과 GraphPFN식 생성기에 Watts–Strogatz, random geometric, graphon 기반 구조를 더해 섞는다. 그래서 GraphPFN prior가 덮지 못한다고 인정한 공간·기하 구조 그래프를 사전학습 분포에 명시적으로 포함한다.
- **Wander** [pretraining-data] Task 간 joint pretraining이 성능을 깎지 않고 일부 task를 돕는다. 같은 학습 step을 준 single-task 모델과 비교하면 KG link prediction과 node classification은 거의 같았고, homogeneous link prediction은 40.37%에서 43.39%로 올랐다. 사전학습 KG에는 node feature가 없었는데도, 추론 때 entity 이름의 MiniLM embedding을 feature로 붙이면 edge type과 결합해 성능이 더 올랐다(WN18RR MRR 0.550에서 0.564, ConceptNet100k 0.258에서 0.334).

평가·분석 연구 중 이 축을 다룬 것 (실험 설계·평가 protocol 참고용):
- **FoundTS** [eval-protocol] 논문마다 조용히 달라지던 protocol 요소를 명시적으로 고정했다. split 비율, normalization, test에서 drop last를 하지 않는 것, few-shot window 샘플링 방식이 그 대상이다. 샘플링 방식만 바꿔도 결과가 크게 달라진다는 것을 직접 보였다. 예를 들어 ETTm1에서 TTM의 MSE가 앞부분 샘플링이면 0.344, 균일 샘플링이면 0.303이었다.
- **FoundTS** [pretraining-data] LLM 기반 TSFM에서 사전학습된 LLM 가중치를 무작위 초기화로 바꾸는 ablation을 했다. 대부분의 LLM 기반 모델은 LLM 가중치를 쓸 때 오히려 나빠지거나 차이가 없었고, 시계열로 사전학습한 모델은 사전학습 효과가 뚜렷했다. 텍스트 사전학습 지식이 forecasting에 주는 이득이 제한적이라는 근거를 통제된 비교로 만들었다.
- **GFM-FairEval** [eval-protocol] GNN baseline을 진지하게 세웠다. 네 가지 고전 구조를 residual·normalization이 들어간 두 codebase로 각각 구현해 8개 variant를 만들고, 데이터셋마다 100 trial TPE 탐색 후 10회 평균±표준편차를 보고한다. 이전 GFM 논문들의 '튜닝 안 된 GNN 대비 우위' 주장을 걸러내는 장치로 작동한다.
- **GFM-FairEval** [eval-protocol] 9개 GFM을 하나의 split·지표·데이터 위에서 공식 구현으로 다시 돌렸다. LLM projection, SVD projection, synthetic edge, 데이터셋별 입출력 모듈, PFN 등 서로 다른 적응 방식을 같은 표에 놓았다. 그 결과 PFN이 아닌 GFM 6개는 분류 normalized score가 3~24 수준인데, 가장 강한 GNN(Crit.-GAT)은 91.5여서 격차가 분명하게 드러난다.
- **GIFT-Eval** [eval-protocol, pretraining-data] test와 겹치지 않는 대규모 사전학습 corpus를 test 벤치마크와 함께 공개했다. 이 corpus로 Moirai를 다시 학습해 누수가 없는 foundation model 비교점을 직접 만들었다. 의도적으로 test 데이터 일부를 넣은 Moirai ablation으로 누수가 성능을 부풀린다는 것도 보였는데, 후속 TSFM-BenchReqs가 이 결과를 긴 horizon과 큰 모델일수록 효과가 커진다는 근거로 인용했다.
- **GIFT-Eval** [eval-protocol] point 지표만 보지 않고 CRPS로 확률 예측을 평가했다. 모든 점수를 Seasonal Naive 대비 비율로 정규화하고, 97개 조합별 순위를 평균 내서 스케일이 큰 데이터셋 하나가 집계를 지배하지 않게 했다.
- **GIFT-Eval** [eval-protocol] foundation model만 비교하지 않고 통계 기법 5종과 dataset별로 학습한 deep learning 모델 8종을 함께 넣었다. deep learning 모델에는 광범위한 hyperparameter search를 했기 때문에, foundation model의 우위가 약한 baseline 덕분이라는 반론을 줄였다.
- **GNNmim** [eval-protocol, observation-mask] Dense raw-feature 평가와 결측 mechanism shift를 제공해 sparse benchmark의 정보 손실 문제를 구분한다.
- **GNNmim** [eval-protocol] 복잡한 대치 없이 mask 입력만 사용하는 강한 비교 대상을 제시한다.
- **NodeGround** [eval-protocol] 데이터셋 규모와 다양성이 지금까지의 GFM 평가 중 가장 넓다. 117개 후보에서 51개로 줄인 5단계 필터 기준을 문서화했다. 남은 데이터셋은 degree가 여러 자릿수에 걸쳐 있고, homophily가 강한 heterophily부터 강한 homophily까지, feature가 희소·밀집 고차원까지, class 분포가 균형부터 심한 불균형까지 퍼져 있다.
- **NodeGround** [eval-protocol] 모든 방법이 같은 split과 seed를 쓰고, supervised 방법은 기본 설정과 201개 설정 튜닝 버전을 함께 보고한다. GCNII, GPRGNN, Polynormer 같은 강한 baseline이 포함되어 있다. 주 지표 외에 macro-F1, cross-entropy 같은 보조 지표도 기록하고, 코드·평가 pipeline·run-level 결과·leaderboard를 공개한다.
- **SpatialContextMemory** [model-based-baseline, observation-mask] 조건부 분산 기준선으로 정보 부족과 fitting 오차를 분리한다.
- **SpatialContextMemory** [eval-protocol, model-based-baseline] 선형장 calibration과 paired 비교를 수행하며 사후 분석을 구분한다.
- **TSAD-OneLiners** [eval-protocol] 평균 점수만 비교하지 않고 시계열별 점수의 상관, effect size, 비열등성 검정까지 봤다. 모든 TSFM과 baseline 쌍에서 시계열별 VUS-PR 상관이 0.90 이상이었고, MOMENT-base-512와 Var-512는 평균 0.311 대 0.313, 상관 0.991이었다. 그래서 TSFM이 비슷한 점수를 낸다는 수준을 넘어 사실상 같은 신호를 낸다고 주장할 수 있었다.
- **TSAD-OneLiners** [eval-protocol, pretraining-data] 결론이 특정 설정의 우연이 아님을 보였다. 다섯 계열, 여러 모델 크기, context 길이를 모두 바꿔도 결과가 같았고, 모델을 키워도 정상 구간과 이상 구간의 복원이 함께 좋아질 뿐 오차 차이는 벌어지지 않았다. MOMENT 사전학습에 들어가지 않은 데이터셋만 따로 봐도 같은 현상이 나타나 데이터 오염으로 설명되지 않는다는 점도 확인했다.
- **TSAD-OneLiners** [eval-protocol] benchmark 자체도 점검했다. TSB-AD-U에서 라벨이 문제인 시계열 50개를 찾았고, VUS-PR이 순위만 보기 때문에 미세한 수치 흔들림이 큰 점수 차이로 증폭되는 사례를 보였다. 집계 지표만 보지 말고 데이터와 점수 곡선을 직접 시각화하라는 권고로 이어진다.
- **TSB-AD** [eval-protocol] 데이터셋 결함을 체계적으로 걸러냈다. 비슷한 패턴에 라벨이 엇갈린 경우, 이상이 하나뿐이거나 끝부분에만 몰린 경우, classification 데이터를 이상탐지용으로 바꾼 경우, 비현실적인 이상 비율 같은 알려진 문제를 제거했다. 남은 1,070개는 당시 최대 규모였던 이전 collection의 거의 두 배이고, 코드와 데이터를 모두 공개했다.
- **TSB-AD** [eval-protocol] 평가 지표 10개를 같은 조건에서 비교해 어떤 지표가 왜 믿기 어려운지 보였다. point adjustment를 쓴 F1에서는 무작위 점수가 비교 방법들 사이에서 26위에 올랐다. VUS-PR은 예측과 라벨 사이 lag에 가장 덜 민감하고 무작위 점수를 우대하지도 않아서 표준 지표로 권고되었다.
- **TSB-AD** [eval-protocol] hyperparameter tuning을 합성 데이터셋 하나가 아니라 모든 데이터셋에서 떼어낸 15% tuning split으로 했다. 40개 알고리즘과 450개 넘는 variant를 같은 전처리와 같은 지표로 비교했기 때문에, 방법마다 다른 데이터셋을 골라 쓰던 기존 비교보다 결과를 믿을 수 있다.
- **TSFM-BenchReqs** [eval-protocol, pretraining-data] TSFM 22개와 데이터셋 401개의 용도를 체계적으로 추적해 데이터 재사용 지도를 처음으로 수치화했다. 모든 모델에 공통으로 깨끗한 평가 데이터셋이 없고, 어디에도 학습용으로 쓰이지 않은 데이터셋이 6%뿐이라는 결과는 기존 zero-shot 비교의 전제를 직접 흔든다.
- **TSFM-BenchReqs** [eval-protocol] 샘플 중복과 다른 두 번째 누수 경로, 즉 같은 기간의 상관된 series로 인한 indirect leakage를 명시적으로 정의했다. 통제 실험에서 누수 신호는 학습 관측 약 20만 5천 개 중 약 1,600개에 불과했는데도 충격 구간의 MAE가 평균 약 217에서 190으로 줄었다. 이 이점은 충격 구간이 지나자 사라져서, 효과가 test 기간 정보 때문이라는 해석을 뒷받침한다.
- **TSFM-BenchReqs** [pretraining-data] 중복이 숨는 구체적 사례를 모았다. Electricity가 Autoformer, Monash, Informer에서 서로 다른 이름으로 쓰이는 경우, Australian Electricity Demand를 1/1000로 줄인 부분집합, 같은 출처를 표기하지만 각각 Lyft와 Uber 데이터인 car ride 데이터셋, 여러 저장소를 거치며 변형된 Solar Alabama 데이터가 그 예다. 벤치마크를 만들 때 바로 쓸 수 있는 점검 목록이 된다.
- **TSFM-BenchReqs** [eval-protocol] 누수가 점수를 얼마나 부풀리는지에 대한 기존 증거를 한곳에 모았다. GIFT-Eval의 Moirai 누수 ablation, 평가 데이터셋 세 개가 TimesFM·UniTS·TTM 사전학습에 들어가 MSE가 47~184% 낮아진 FoundTS 사례, 사전학습에 포함된 스페인 에너지 데이터에서 Chronos가 TiDE보다 훨씬 좋았던 사례가 포함된다.
- **TSFM-BenchReqs** [eval-protocol] 요건이 구체적이고 실행 가능하다. 사전학습 데이터를 규제하지 않으면서, 비교 대상 모델들의 학습 시점에 맞춰 test 구간을 정하는 model-aware 전역 cutoff를 제안했다. 미리 정한 고정 날짜가 아니라 비교하는 모델 집합에 따라 cutoff가 정해진다.

## 2. 동기로 인용할 수 있는 한계
이 아이디어가 겨냥하는 축에서 기존 논문이 약하다고 확인된 지점이에요. 후속 논문·리뷰 지적이 가장 강한 근거입니다.

- **FoundTS** (후속 논문 지적 — Rethinking Evaluation in the Era of Time Series Foundation Models: (Un)known Information Leakage Challenges (2025)) [eval-protocol, pretraining-data] 벤치마크를 만든 쪽이 평가 데이터셋 세 개가 이미 TimesFM, UniTS, TTM의 사전학습에 쓰였다는 것을 모른 채 포함했다고 지적했다. TSFM의 사전학습 데이터 구성을 파악하기 어려운 탓으로 보았다. 그 결과 이 모델들은 해당 데이터셋에서 누수가 없는 최고 모델보다 MSE가 47%에서 184%까지 낮았다. 누수가 없는 데이터셋에서 최고 TSFM의 이점은 0.3%에서 14%에 그쳤다. 이 사례는 FoundTS arXiv판을 인용한 것이다. 같은 논문은 KDD판 TSFM-Bench를 series마다 시간 split을 한 번만 하는 series 중심 평가의 예로도 분류했다.
- **FoundTS** (후속 논문 지적 — TS-Arena: A Live Forecast Pre-Registration Platform (2025)) [eval-protocol, pretraining-data] TSFM-Bench가 정보 누수를 다루지도 논의하지도 않는다고 지적했다. 평가 데이터셋이 TSFM의 사전학습과 평가에 흔히 쓰이는 잘 알려진 데이터셋으로 구성되어 있다는 점도 함께 들었다.
- **FoundTS** (후속 논문 지적 — Position: Time-Series Foundation Models Require Explicit Domain-Level Benchmarks (ICML 2026)) [eval-protocol] GIFT-Eval, Monash와 함께 TSFM-Bench를 도메인별로 고르지 않게 섞은 집계형 leaderboard로 분류했다. 이런 집계는 healthcare, finance, energy 같은 개별 도메인 성능을 가려서 전체 점수가 모델 선택을 오도할 수 있다고 주장했다. 이 비판은 초록에서 확인했다.
- **GFM-FairEval** (후속 논문 지적 — NodeGround: A Node Classification Benchmark in the Graph Foundation Model Era (2026)) [eval-protocol] NodeGround의 benchmark 비교표는 이 논문을 benchmark가 아닌 평가 protocol로 분류한다. 그 표에서 이 논문은 node classification 데이터셋 4개, split 설정 1개로 집계되고, 다중 지표 평가와 leaderboard는 없으며 run-level 결과 공개는 부분적이라고 표시된다. Hyperparameter 탐색 통제, validation 기반 선택, 학습·tuning·추론 비용 측정은 모두 충족으로 표시된다.
- **GIFT-Eval** (후속 논문 지적 — Rethinking Evaluation in the Era of Time Series Foundation Models: (Un)known Information Leakage Challenges (2025)) [eval-protocol, pretraining-data] GIFT-Eval을 series를 많이 모으고 각 series는 시간상 한 번만 나누는 방식의 대표 사례로 분류했다. 저자들은 시간과 series를 함께 교차검증하는 방식을 best practice로 보는데 GIFT-Eval은 여기에 해당하지 않는다. 또 GIFT-Eval의 leak-free corpus를 포함한 기존 누수 대책이 누수 경로를 체계적으로 분석하지 않은 사후 대응이라고 평가했다. 구체적 사례로 Solar를 들었다. GIFT-Eval은 Alabama 부분집합을 test로 쓰는데 Chronos 사전학습에는 미국 전체 주의 solar 데이터가 들어 있고, 변형된 Alabama 버전은 Monash를 거쳐 TinyTimeMixers와 Lag-Llama 사전학습에도 쓰였다. Sundial은 GIFT-Eval과의 중복을 제거했다고만 밝히고 목록은 공개하지 않았다.
- **GIFT-Eval** (후속 논문 지적 — It's TIME: Towards the Next Generation of Time Series Forecasting Benchmarks (ICML 2026)) [eval-protocol] GIFT-Eval처럼 도메인·frequency 같은 고정된 meta label로 데이터셋을 묶으면, 서로 다른 도메인의 변수들이 비슷한 시간 패턴을 보이는 경우가 많아서 왜 모델이 잘하는지 설명하지 못한다고 지적했다. frequency에 비례해 horizon을 정하는 GIFT-Eval 방식도 실제 예측 요구와 분리된 일률적 설정으로 보았다. 기존에 공개된 데이터셋을 다시 모은 구성이라 사전학습 corpus에 일부 흡수됐을 가능성이 크고, task 단위 집계는 집계 수준에 따라 순위가 크게 바뀐다는 점도 함께 들었다. GIFT-Eval 저자 중 한 명(Chenghao Liu)이 참여한 후속 연구다.
- **GIFT-Eval** (후속 논문 지적 — QUITOBENCH: A High-Quality Open Time Series Forecasting Benchmark (2026)) [eval-protocol] trend, seasonality, forecastability를 각각 high/low로 나눈 8개 regime으로 보면 GIFT-Eval series의 50.7%가 셋 다 low인 한 칸에 몰려 있다고 지적했다. series의 절반은 길이가 200 미만이라 긴 context를 평가할 수 없다. 겹치지 않는 window를 최대 20개까지만 쓰기 때문에 long horizon에서는 series당 평가 window가 한두 개뿐이고, 그래서 headline 점수가 평가 시점 선택에 민감하다고 보았다.
- **GIFT-Eval** (후속 논문 지적 — fev-bench: A Realistic Benchmark for Time Series Forecasting (2025)) [eval-protocol] GIFT-Eval을 가장 포괄적인 기존 범용 forecasting 벤치마크로 인정하면서도, covariate가 있는 task가 하나도 없다는 점을 비교표로 보였다. frequency 분포에서도 1분·30분 단위 task가 없다. 기존 벤치마크 전반의 집계가 단일 숫자 요약에 그쳐 통계적 엄밀성이 부족하다는 비판도 했는데, 이것은 GIFT-Eval만 지목한 문장은 아니다.
- **Moirai** (후속 논문 지적 — GIFT-Eval: A Benchmark For General Time Series Forecasting Model Evaluation (2024)) [eval-protocol, pretraining-data] GIFT-Eval에서 Moirai는 foundation model 중 유일하게 multivariate 예측을 지원해서 다변량 데이터에서 다른 foundation model보다는 나았지만, 다변량 데이터 전체의 1위와 2위는 PatchTST와 iTransformer였다. 도메인별로는 Moirai와 Chronos가 대부분 상위였으나 Transport와 Web/CloudOps에서는 PatchTST, TFT 같은 deep learning 모델이 앞섰고, 저자들은 이 도메인 데이터의 높은 entropy와 lumpiness, 사전학습 데이터 부족을 원인으로 추정했다. Moirai의 사전학습 데이터가 GIFT-Eval 평가 데이터와 일부 겹친다는 점도 명시했다. GIFT-Eval에는 Moirai 저자 6명 중 5명이 참여했다.
- **MOMENT** (후속 논문 지적 — The Elephant in the Room: Towards A Reliable Time-Series Anomaly Detection Benchmark (NeurIPS 2024 Datasets and Benchmarks)) [eval-protocol] MOMENT의 사전학습 데이터에 anomaly detection 데이터셋이 포함되어 있어 평가 데이터 오염 위험을 주요 우려로 제기했다. 단변량 벤치마크에서는 MOMENT가 foundation model 중 유일하게 상위권에 들었지만 Sub-PCA, KShapeAD, POLY 같은 단순 통계 기법보다는 아래였다. 다변량 벤치마크에서는 상위 12개 안에 들지 못했다.
- **NodePFN** (후속 논문 지적 — A Fair Evaluation of Graph Foundation Models for Node Property Prediction (2026)) [pretraining-data] NodePFN이 약한 이유로 세 가지를 가설로 든다. 첫째, sample 하나를 token 하나로 보는 TabPFN v1 시절 구조를 쓴다. 둘째, 강한 tabular FM에서 초기화하지 않고 처음부터 학습한다. 셋째, GraphPFN보다 prior가 단순하다. 이 이유로 자신들의 공정 비교 평가에서는 NodePFN을 아예 제외했다. 검증된 원인이 아니라 저자들의 추정이라는 점은 감안해야 한다.
- **NodePFN** (후속 논문 지적 — NodeGround: A Node Classification Benchmark in the Graph Foundation Model Era (2026)) [eval-protocol] 원 논문의 평가는 5만 node 미만 그래프에 한정되고 GNN baseline도 두 개뿐이라, GFM의 실제 경쟁력을 판단하기에 부족했다고 지적한다.
- **Sundial** (후속 논문 지적 — Rethinking Evaluation in the Era of Time Series Foundation Models: (Un)known Information Leakage Challenges (2026)) [eval-protocol] Sundial 저자들이 GIFT-Eval과 겹치는 데이터를 제외했다고 밝히면서도 어떤 데이터셋을 뺐는지 목록을 제시하지 않았다고 지적한다. 같은 데이터가 저장소마다 다른 이름으로 올라와 있는 상황에서는 제외 여부를 외부에서 검증할 수 없다는 것이 요지다. 데이터셋 동일성 확인이 어렵다는 점을 명시하고 해당 데이터를 뺀 TiRex·Toto와 대비된다.
- **Time-MoE** (후속 논문 지적 — Moirai-MoE: Empowering Time Series Foundation Models with Sparse Mixture of Experts (ICML 2025)) [eval-protocol] Time-MoE가 기존 gating 함수를 그대로 가져다 썼을 뿐 새로운 gating을 제안하거나 MoE 내부 동작을 분석하지 않았다고 지적한다. point-wise tokenization은 시계열의 의미 단위를 담지 못해 성능을 제한할 수 있다고도 본다. 실제로 사전학습에 쓰이지 않은 10개 데이터셋 zero-shot 평가에서, 누수 데이터셋을 뺀 평균 MASE(seasonal naive 대비 정규화)는 Time-MoE base·large 모두 0.695였다. 이는 Moirai-MoE base(0.611)뿐 아니라 TimesFM(0.640), Chronos-base(0.631), Moirai-large(0.685)보다도 나쁜 값이다. 이 표에서 Electricity와 Solar는 Time-MoE의 사전학습에 포함된 non-zero-shot 데이터셋으로 표시되었다. 다만 Time-MoE는 context를 4,096으로 고정했고 Moirai 계열은 context를 탐색했다.
- **TimesFM** (후속 논문 지적 — Unified Training of Universal Time Series Forecasting Transformers (Moirai, 2024)) [pretraining-data] 사전학습 데이터가 Google Trends와 Wiki pageview에 크게 의존해서 시계열이 나온 도메인의 다양성이 부족하다고 지적한다. 비교표에서도 TimesFM을 any-variate zero-shot과 probabilistic forecasting을 지원하지 않는 모델로 분류한다.
- **TimesFM** (후속 논문 지적 — GIFT-Eval: A Benchmark For General Time Series Forecasting Model Evaluation (2024)) [eval-protocol] GIFT-Eval에서 TimesFM은 medium·long horizon으로 갈수록 성능이 크게 떨어졌다. 저자들은 decoder-only 구조의 recursive multi-step 예측에서 오차가 누적되기 때문이라고 해석한다. 또한 TimesFM 사전학습 데이터가 GIFT-Eval test 데이터와 일부 겹친다고 표시했다.
- **TimesFM** (후속 논문 지적 — Moirai-MoE: Empowering Time Series Foundation Models with Sparse Mixture of Experts (2025)) [eval-protocol] TimesFM이 frequency embedding으로 데이터를 frequency 단위로 구분하는 방식을 사람이 정한 heuristic이라고 비판한다. frequency가 실제 패턴을 잘 대변하지 못하고, non-stationary 시계열에는 frequency 단위 구분이 너무 거칠다는 것이 근거다. 평가에서도 TimesFM의 Monash와 Electricity 결과에 사전학습 데이터 중복 표시를 달았다.
- **TimesFM** (후속 논문 지적 — Rethinking Evaluation in the Era of Time Series Foundation Models: (Un)known Information Leakage Challenges (arXiv v3; v2 제목 Challenges and Requirements for Benchmarking TSFMs)) [eval-protocol] 기존 한 벤치마크가 TimesFM(및 UniTS, TTM)의 사전학습에 이미 쓰인 데이터셋 3개를 test로 써서, 해당 모델들이 누수 없는 최고 모델보다 MSE가 47~184% 낮게 나왔다고 추정한다. 누수 없는 데이터셋에서는 최고 TSFM의 우위가 0.3~14%에 그쳤다. Monash의 Australian Electricity Demand처럼 어떤 모델은 사전학습에, TimesFM은 zero-shot 평가에 쓰는 데이터셋은 모델 간 비교에 쓸 수 없다고도 지적한다.
- **TSB-AD** (후속 논문 지적 — When Foundation Models are One-Liners: Limitations and Future Directions for Time Series Anomaly Detection (ICLR 2026)) [eval-protocol] TSB-AD-U 평가 시계열 중 50개에서 라벨 문제를 찾았다. 47개는 이상 라벨이 정상 구간과 임의로 겹쳤고, UCR 시계열 3개는 라벨이 한 칸씩 어긋나 있었다. 또 VUS-PR은 점수의 순위만 보기 때문에, 한 번의 spike를 빼면 일정한 시계열에서 10^-5 수준의 미세한 흔들림만으로 점수가 0.05에서 0.51로 뛰는 사례를 보였다. 문제 시계열을 빼면 forecasting 기반 TSFM과 단순 baseline 사이의 격차도 줄었다.
- **TSB-AD** (후속 논문 지적 — TAB: Unified Benchmarking of Time Series Anomaly Detection Methods (PVLDB 2025)) [eval-protocol] 후속 benchmark의 비교표에서 TSB-AD는 zero-shot과 few-shot 평가 protocol이 없는 benchmark로 분류되었다. foundation model을 평가 대상에 넣은 점은 인정했지만, 학습 데이터가 없거나 적은 조건에서 방법들을 체계적으로 비교하는 축은 없다는 지적이다. TSB-AD 안에 zero-shot MOMENT 결과는 있지만 protocol 차원의 비교 축은 아니다.
- **TSB-AD** (후속 논문 지적 — Did We Actually Fix It? An Independent Adversarial Stress-Test of Post-Point-Adjustment Evaluation Metrics for Time-Series Anomaly Detection (2026)) [eval-protocol] TSB-AD가 권고한 VUS-PR을 무작위 점수와 best-of-N seed 선택으로 공격해 봤다. UCR, SMD, SMAP, MSL에서는 대체로 버텼지만, NAB에서는 시도 횟수를 늘리면 부풀려지는 시계열 비율이 25%에 이르렀다. 한 benchmark에서 안전한 지표가 다른 benchmark에서도 안전하다는 보장은 없다는 결론이다. TSB-AD의 지표 분석은 독립적이거나 adversarial한 감사가 아니었다고 분류했다.
- **Chronos-2** (저자 인정) [pretraining-data] 단변량을 넘어서는 능력은 전적으로 synthetic 데이터에 기대고 있다고 저자들이 명시한다. synthetic만으로 학습한 변형은 fev-bench skill score가 45.9%로 본 모델(47.3%)보다 낮아, 실제 데이터가 여전히 기여한다는 점도 저자들 ablation에 나타난다.
- **Chronos-2** (저자 인정) [eval-protocol] 학습 corpus가 GIFT-Eval test 구간과는 겹치지 않지만 일부 GIFT-Eval 데이터셋의 train 구간과는 부분적으로 겹친다고 저자들이 밝힌다.
- **GFM-FairEval** (저자 인정) [eval-protocol] 평가한 GFM 목록이 망라적이지 않아서, 더 새로운 모델이나 동시기 모델은 빠졌을 수 있다고 저자들이 인정한다.
- **GFM-FairEval** (저자 인정) [eval-protocol] 실험이 GraphLand 하나에만 기대고 있어서, 사내 데이터·특수 도메인·feature 유형이나 분포가 다른 데이터셋으로 결론이 일반화되지 않을 수 있다고 저자들이 밝힌다.
- **GIFT-Eval** (저자 인정) [eval-protocol, pretraining-data] TimesFM, Chronos, Moirai의 공개 사전학습 데이터가 GIFT-Eval test와 부분적으로 겹친다고 저자들이 인정했다. 누수 영향은 부록에서 따로 분석했지만, 본문 결과표에는 누수 상태가 서로 다른 공개 모델들이 같은 기준으로 나란히 들어가 있다.
- **GIFT-Eval** (저자 인정) [eval-protocol] 데이터셋 성격 분석에 쓴 tsfeatures가 매우 긴 series에서는 yearly seasonal strength를 계산하지 못해, 저주파 데이터의 seasonality 기술이 빠져 있다고 저자들이 밝혔다.
- **GraphPFN** (저자 인정) [pretraining-data] 부록의 prior ablation에서 단순 degree-corrected SBM으로 사전학습해도 제안한 multi-level SBM + PA prior와 비슷하거나 일부 데이터셋에서 더 좋았다. 저자들도 이전 revision과 결과가 달라졌음을 인정하고, 제안 prior는 일관성과 다양성 때문에 유지했다고 설명한다. 즉 새 graph prior의 성능상 기여는 최종본에서 뒷받침되지 않는다.
- **Moirai** (저자 인정) [pretraining-data] LOTSA의 도메인과 frequency 다양성을 더 늘려야 한다고 인정했다. 실제로 관측치의 59%가 Energy 도메인, 72%가 hourly 계열에 몰려 있다.
- **Moirai** (저자 인정) [eval-protocol, pretraining-data] LOTSA에 PeMS 기반 대규모 데이터(LargeST)를 넣었기 때문에 PEMS03/04/07/08, PEMS-Bay, 장기 예측 벤치마크의 Traffic처럼 같은 출처의 데이터셋은 더 이상 zero-shot 평가로 볼 수 없다고 저자들이 명시했다. 그래서 장기 예측 평가에서 Traffic을 뺐다.
- **Moirai** (저자 인정) [eval-protocol] zero-shot 비교 대상이 다른 universal forecaster가 아니라 각 데이터셋에서 학습한 full-shot 모델이다. 저자들은 공개 가중치가 있는 universal forecaster가 거의 없고, 모든 모델이 보지 않은 표준 held-out 데이터셋도 없어서 공정한 비교가 어렵다고 설명했다.
- **NodeGround** (저자 인정) [eval-protocol] 고정된 라벨 예산과 공유 split에서의 node classification만 다룬다. 라벨 노드와 query 노드가 다른 community나 다른 시점에서 오는 non-IID 설정은 담지 못한다고 저자들이 인정한다.
- **PFNSeparability** (저자 인정) [eval-protocol] Production PFN이 비분리성에서 실제로 얼마나 이득이나 손해를 얻는지는 미확인이라고 저자가 명시한다.
- **SpatialContextMemory** (저자 인정) [eval-protocol, model-based-baseline] 비선형 spatial gap은 학습한 global FNO 기준 추정이며 최적성을 검증하지 못했다.
- **SpatialContextMemory** (저자 인정) [eval-protocol] 일부 KS 비교는 pilot 이후 설계했고 기존 test trajectory를 재사용했다.
- **SSGP** (저자 인정) [eval-protocol] §3.3의 실험은 geometry의 전체 evidence 대신 conditional evidence를 사용한다.
- **Sundial** (저자 인정) [pretraining-data] TimeBench에는 중·저주파 시계열이 많아서 아주 고주파인 데이터에서의 성능은 보장할 수 없다고 저자들이 인정한다. 모델 용량을 키웠어도 hallucination이 생길 수 있다고 밝히며, 다중 스케일 시계열로의 일반화를 중요한 향후 과제로 든다.
- **TSB-AD** (저자 인정) [eval-protocol] 저자들은 어떤 benchmark도 완벽하지 않다고 인정했다. 수작업 검수가 소수의 숙련된 시계열 사용자에게 의존했다는 점을 한계로 들고, 앞으로도 dataset 정제 방식을 계속 다듬겠다고 밝혔다.
- **TSB-AD** (저자 인정) [eval-protocol, pretraining-data] foundation model은 사전학습 corpus가 커서 TSAD 데이터셋이 섞여 들어갈 수 있고, 이 데이터 오염이 가장 큰 우려라고 저자들이 직접 밝혔다. 실제로 MOMENT의 사전학습 데이터에는 anomaly detection 데이터셋이 포함되어 있다. 따라서 foundation model의 순위는 이 단서를 달고 읽어야 한다.
- **TSFM-BenchReqs** (저자 인정) [eval-protocol] test set 오염의 효과 크기는 몇몇 고립된 사례에서만 유의하게 확인됐다고 저자들이 인정했다. 실제 TSFM 환경에서 temporal leakage가 얼마나 큰지는 대부분 알려져 있지 않고, 도메인과 사건 유형에 따라 다를 것이라고 했다. 부록에서 제시한 Monash 데이터의 시간 중복 사례도 이론적 가능성일 뿐 효과를 측정하지는 않았다.
- **TSFM-BenchReqs** (저자 인정) [eval-protocol] COVID 통제 실험은 기존 TSFM이 아니라 처음부터 학습한 작은 Transformer로 했다고 저자들이 밝혔다. Madrid 교통 사례(MAE 약 43% 개선)는 누수에 거의 이상적인 조건이었다고도 인정했다. 대규모 TSFM이 더 취약할 것이라는 주장은 실험하지 않은 추론이다.
- **Wander** (저자 인정) [pretraining-data] 사전학습 prior가 아직 좁다. Attributed graph는 대부분 synthetic이고, multi-relational 사전학습은 실제 KG 세 개뿐이다. 저자들은 node feature와 edge type을 함께 가진 그래프 쪽으로 prior를 넓히는 것을 향후 과제로 든다.
- **Chronos-2** (조사자 판단) [eval-protocol] [analyst] 평가의 독립성이 약하다. 헤드라인 결과인 fev-bench는 저자 8명 중 7명이 Chronos-2 저자와 겹치는 논문에서 나왔고, Chronos Benchmark II는 Chronos 논문의 벤치마크다. 외부 벤치마크인 GIFT-Eval에서는 train 구간 일부가 겹치고, TimesFM-2.5와의 WQL skill 차이도 51.4% 대 51.0%로 작다. 게다가 GIFT-Eval에서는 group attention 유무로 성능이 거의 변하지 않았다는 후속 보고가 있다. 그러므로 multivariate·covariate 능력의 우위는 사실상 fev-bench covariate subset 하나에 크게 기대고 있다.
- **Ephris** (조사자 판단) [eval-protocol, observation-mask] [analyst] 본문에서 우리의 severe whole-node/clustered feature missing 프로토콜에 대한 성능은 확인하지 못했다.
- **FoundTS** (조사자 판단) [eval-protocol] [analyst] horizon마다 여러 lookback 중 가장 좋은 결과를 보고하는데, 그 선택을 validation에서 했는지 test에서 했는지 본문에 밝히지 않았다. test 기준 선택이라면 설정 조합이 많은 모델일수록 유리한 낙관적 편향이 생긴다. zero-shot 모델과 dataset별 모델 모두 이 선택의 혜택을 받으므로 순위 비교에도 영향을 줄 수 있다.
- **FoundTS** (조사자 판단) [eval-protocol] [analyst] few-shot 설정은 학습 구간의 5%만 쓰지만 validation 구간은 전부 쓴다. split이 7:1:2라면 학습에 쓰는 양은 전체의 약 3.5%이고 validation은 10%다. early stopping과 모델 선택에 학습 데이터보다 큰 validation을 쓰는 셈이라, 실제 데이터가 부족한 상황의 few-shot과는 다르다.
- **GFM-FairEval** (조사자 판단) [eval-protocol] [analyst] '튜닝된 GNN을 넘는 건 PFN 계열뿐'이라는 결론은 분류 데이터셋 4개 중 3개가 binary인 구성 위에 서 있다. 또 baseline GNN 풀에 GCNII·GPRGNN 같은 계열이 없다. 51개 데이터셋을 쓴 NodeGround에서는 튜닝된 GCNII·GPRGNN이 전체 1·2위였고, GraphPFN의 우위는 binary task에 몰려 있었다. 따라서 이 논문의 결론은 데이터셋 구성과 GNN 풀에 따라 뒤집힐 수 있고, multiclass·다중 class 조건에서는 뒷받침되지 않는다. 또한 저자 4명 모두 GraphPFN 저자이고, G2T-FM(Eremeev et al.)과 GraphLand(Bazhenov et al.)도 이 저자들이 1저자인 이전 작업이다.
- **GFM-FairEval** (조사자 판단) [eval-protocol] [analyst] 비용 논증이 정성적이다. GNN은 100 trial, GraphPFN finetuning은 learning rate 10개만 탐색한 상태에서 tuning 시간을 비교한다(예: city-reviews에서 1.08일 대 1.88일). 같은 compute 예산에서 GNN을 덜 튜닝했을 때 성능이 어떤지는 보여주지 않는다. NodeGround의 budget curve 분석에서는 10/10/80 split에서 부분 튜닝한 supervised 방법이 비용 대비 성능 frontier에서 GraphPFN을 앞질렀다.
- **GGP** (조사자 판단) [observation-mask] [analyst] Feature 관측 mask의 공동 likelihood와 target 재학습 없는 PFN 전이는 검증하지 않는다.
- **GIFT-Eval** (조사자 판단) [eval-protocol] [analyst] multivariate 평가가 매우 얇다. test series 144,246개 중 140,711개가 univariate이고, 2변량이 3,522개, 7변량이 10개, 21변량이 3개뿐이다. 변수 7개 이상인 series가 13개밖에 없어서 cross-channel 모델링 능력은 사실상 검증되지 않는다. univariate 모델에는 multivariate 데이터를 펼쳐서 넣으므로 multivariate 결과도 channel-independent 처리와의 비교에 가깝다.
- **GIFT-Eval** (조사자 판단) [eval-protocol, pretraining-data] [analyst] 도메인별 우열 차이를 사전학습 데이터 구성 차이로 설명하지만, 같은 corpus로 학습한 비교는 Moirai 한 계열뿐이다. TimesFM, Chronos, VisionTS는 서로 다른 데이터로 학습한 공개 checkpoint를 그대로 썼기 때문에 아키텍처 효과와 데이터 효과를 분리할 수 없다.
- **GraphPFN** (조사자 판단) [eval-protocol] [analyst] ICL만 놓고 보면 G2T-LimiX 대비 우위가 크지 않다. GraphLand 전체 평균 rank는 3.50 대 3.88이고, tolokers-2·avazu-ctr·city-roads-M에서는 G2T-LimiX가 앞선다. 헤드라인의 큰 격차는 대부분 finetuning에서 나온다. 또 twitch-views처럼 random feature 추가 여부로 성능이 크게 바뀌는 데이터셋이 있어, 일부 이득은 추론 시 trick에도 기대고 있다.
- **LoGIC** (조사자 판단) [eval-protocol] [analyst] Context 선택이 가장 중요해질 multiclass 분류가 사실상 평가되지 않았다. 주 실험의 GraphLand 8개는 binary classification 3개와 regression 5개다. 유일한 multiclass인 pokec-regions(183 class)는 규모 시연이며, 어떤 backbone을 썼는지와 10개 class 제한을 어떻게 넘었는지가 본문에 없고 학습된 baseline도 없다. Coverage channel도 uniform sample이라서 라벨 분포를 기댓값으로만 보존하고 class coverage는 보장하지 않는다. 논문이 언급한 class별 stratified 변형은 보고된 결과에 쓰이지 않았고, PPR·feature-kNN에는 class 균형 장치가 없다. 따라서 query 묶음마다 context 라벨 분포가 달라질 수 있지만, 그 영향과 minority class 동작은 분석되지 않았다.
- **LoGIC** (조사자 판단) [eval-protocol] [analyst] Full context 대비 이득은 대부분 0.3점 이내이고, 가장 큰 이득은 twitch-views에서 나왔다. 그런데 k=4096 channel 비교에서 twitch-views의 최선 channel은 PPR이나 feature-kNN이 아니라 uniform random인 coverage였다(72.00 대 PPR 70.20, feature-kNN 68.95). 그래서 정교한 retrieval의 효과와 backbone이 너무 긴 context에서 나빠지는 효과가 분리되지 않는다. TAG식 random subsampling이나 LoCalPFN식 per-query kNN retrieval과 같은 예산에서 정면 비교한 실험도 없다.
- **Moirai-MoE** (조사자 판단) [eval-protocol] [analyst] 성능 향상이 MoE에서 왔다는 결론이 ablation으로 충분히 분리되지 않았다. Monash 정규화 MAE로 보면 multi projection 상태에서 dense를 MoE로 바꾼 효과는 0.75에서 0.72였고, MoE 안에서 multi projection을 single patch 16으로 바꾼 효과는 0.72에서 0.65로 더 컸다. 그런데 dense decoder에 single patch 16만 적용한 구성은 보고하지 않았다. routing centroid를 얻기 위해 single projection dense 모델을 이미 학습했는데도 그 성능은 나와 있지 않다. 원래 Moirai와 비교할 때는 batch 크기(256에서 1,024)와 학습 step 수도 달라서, 개선폭에는 학습 설정 차이도 섞여 있다.
- **Moirai-MoE** (조사자 판단) [eval-protocol] [analyst] 다변량 처리에 대한 근거가 거의 없다. 변수를 펴서 causal attention을 한다는 한 문장 외에는 변수 간 causal mask를 어떻게 정의하는지, covariate를 어떻게 넣는지 설명이 없다. 단순히 펴서 causal mask를 걸면 변수 순서에 따라 볼 수 있는 정보가 달라지는데 이를 어떻게 처리했는지 알 수 없다. 다변량 정보가 도움이 되는지 확인하는 실험도 없고, 평가는 단변량인 Monash와 context length를 validation으로 고른 zero-shot 설정이 중심이다.
- **Moirai** (조사자 판단) [eval-protocol] [analyst] zero-shot 결과의 상당 부분이 target 데이터셋의 validation 구간으로 추론 설정을 고른 결과다. 확률 예측에서는 context length(1000~5000)와 patch size를 validation CRPS로 골랐고, 장기 예측에서는 ETT와 Weather에 대해 channel-independent와 channel mixing 중 무엇을 쓸지까지 validation MSE로 골랐다. 고정된 context로 평가하는 다른 zero-shot 모델과 같은 기준이라고 보기 어렵고, 어느 전략이 선택됐는지도 보고하지 않는다.
- **MOMENT** (조사자 판단) [eval-protocol, pretraining-data] [analyst] Time-series Pile에는 평가에 쓰인 ETT, Electricity, Traffic, Weather, UCR 데이터셋의 train split이 그대로 들어 있다. test split은 분리했으므로 엄밀한 누수는 아니다. 그래도 장기 예측, classification, imputation 결과는 같은 데이터셋의 다른 구간을 본 in-distribution 성능에 가깝고, 처음 보는 도메인으로의 일반화를 보여주지는 않는다.
- **NodeGround** (조사자 판단) [eval-protocol] [analyst] 본문 서술상 GFM은 공개 가중치를 그대로 두고 인터페이스 선택지만 튜닝한다. 반면 supervised 방법은 201개 설정으로 튜닝한다. GFM-FairEval에서는 GraphPFN finetuning이 거의 항상 성능을 올렸고 GraphLand 10개 데이터셋 모두에서 1위였다. 그러므로 '튜닝된 GNN이 GFM보다 낫다'는 결론은 가중치를 고정한 GFM과 충분히 튜닝한 GNN의 비교로 읽어야 한다. GraphPFN finetuning 여부는 부록 C.4에 있을 것으로 보이는데, 이번 조사에서는 확인하지 못했다.
- **NodeGround** (조사자 판단) [eval-protocol] [analyst] '심한 불균형 target' 부분집합의 정의(통계량과 기준값)는 본문에 없고 부록 B.4로 미뤄져 있다. 또 multiclass 주 지표가 accuracy라서, 불균형 조건의 순위는 다수 class를 맞히는 능력에 크게 좌우될 수 있다. Macro-F1은 보조 지표로만 기록된다. 결측 결과를 default GCN 값으로 채운 건수도 본문에 없다. 이 때문에 GraphPFN의 10개 초과 class 약점이 실제 예측 결과인지, 대체값이 섞인 것인지 본문만으로는 구분되지 않는다.

- **TimesFM** (조사자 판단) [eval-protocol] [analyst] 긴 horizon에 대한 근거가 좁다. 주 zero-shot 비교는 ETT 4개 데이터셋의 horizon 96과 192뿐이고, 512 step 예측은 출력 patch 길이 ablation에서만 다룬다. 출력 patch를 길게 잡은 설계가 장기 예측의 누적 오차를 충분히 막는지는 이후 GIFT-Eval 결과를 보면 의문이 남는다.
- **TSAD-OneLiners** (조사자 판단) [eval-protocol] [analyst] TSPulse 결과는 직접 돌리지 않고 원 논문의 수치를 가져왔다. context 길이도 512 하나뿐이다. 다른 네 계열과 전처리·평가 설정이 완전히 같다고 보기 어려우므로, TSPulse에 대한 결론은 다른 계열보다 약하게 읽어야 한다.

- **TSB-AD** (조사자 판단) [eval-protocol] [analyst] foundation model을 다변량 시계열에 어떻게 적용했는지 본문에 설명이 없다. TSB-AD-M 상위 12개에 foundation model이 하나도 없지만, channel별로 따로 돌렸는지조차 알 수 없어서 다변량에서 foundation model이 약하다는 해석까지는 내릴 수 없다. 다변량 subset도 200개로 단변량 870개보다 훨씬 작아서, 다변량 순위는 단변량 순위보다 흔들리기 쉽다.
- **TSFM-BenchReqs** (조사자 판단) [eval-protocol] [analyst] 이 논문은 요건을 제시하지만 요건을 만족하는 평가에서 기존 모델 순위가 실제로 바뀐다는 것은 보이지 않았다. 누수가 개별 사례에서 점수를 부풀린다는 것과 leaderboard 결론이 틀렸다는 것은 다른 주장이다. 같은 저자들의 후속 TS-Arena가 실시간 사전 등록 방식으로 이 간극을 메우려 한다.
- **TSFM-BenchReqs** (조사자 판단) [eval-protocol] [analyst] 전역 cutoff 요건은 실무 비용이 크다. 가장 최근에 학습한 모델이 cutoff를 정하므로 새 모델이 추가될 때마다 test 구간이 뒤로 밀리고 짧아진다. 짧은 최근 구간은 특정 regime 하나에 치우치기 쉬워 nonstationarity가 평가를 흔든다. 또 각 모델의 학습 데이터 마지막 시점이 정확히 공개되어야 하는데, 논문이 직접 든 Sundial 사례처럼 제외한 데이터 목록조차 공개되지 않는 경우가 있다.
- **TSFM-Survey** (조사자 판단) [pretraining-data] [analyst] 같은 모델에 대한 서술이 절마다 어긋난다. MOMENT는 한 절에서 단변량 전용이라고 하면서 다른 절에서는 channel을 독립적으로 처리해 다변량을 다룬다고 쓴다. MOIRAI의 loss는 categorical cross-entropy와 log-likelihood로 엇갈리고, TimesFM의 사전학습 데이터 규모도 본문은 200B, Table 2는 100B로 다르다. Table 2의 값은 원 논문과 대조한 뒤에 써야 한다.
- **TSFM-Survey** (조사자 판단) [eval-protocol] [analyst] 단변량·다변량 축이 '채널을 독립적으로 처리하는 모델'과 '변수 간 의존성을 학습하는 모델'을 구분하지 못한다. MOMENT 서술이 엇갈리는 것도 이 때문이다. 평가 benchmark, 사전학습 데이터와 test set의 중복, 실험 비교는 다루지 않는다. Moirai-MoE, Sundial, Chronos-Bolt, TimesFM 2.0도 빠져 있어서 최신 모델 비교에는 쓰기 어렵다.
- **UniSTD** (조사자 판단) [eval-protocol] [analyst] Method는 예측 전에 입력 feature를 만들거나 갱신하기 위한 graph propagation이 남을 수 있다고 명시한다. Graph-free forward와 전체 파이프라인의 graph-free 비용을 구분해야 한다.

  - 기준선 / 최소 재검증: Vanilla continuation, matched/log/diagonal, covariance-shuffled controls / 분류 성능을 바꾸는 source dependency task에서 correspondence control과 새 graph·seed를 함께 비교한다.
  - 원문: findings/sources/graphpfn-2026-11-01/source_error.md

- **FMARG-L01** (Frozen GraphPFN joint feature-completion marginalization) [eval-protocol, observation-mask] 분포형 input을 적용한 frozen 연산의 성과와 Bayesian posterior·새 학습법을 구분한다.

- **FMARG-L02** (Frozen GraphPFN joint feature-completion marginalization) [eval-protocol] 노드 간 covariance의 진단은 per-cell variance와 일반 ensemble 효과를 통제한다.
  - Joint와 diagonal에 같은 rho draws·조건부 평균·대각 분산·standard normal draws를 주고 rho 내 off-diagonal covariance만 바꿨다. 두 arm 모두 rho는 graph 공유다. 관측값 clamp·conditional moment node permutation·12000-draw covariance sanity를 확인했다. 이것이 새 정보나 method superiority를 입증하지는 않는다.
- **FMEM-L01** (Label-context와 observed-feature memory 분리) [eval-protocol, observation-mask, feature utility] 더 넓은 key/value 접근의 구현 가능성과 실제 feature utility를 구분한다.

- **JIMP-L01** (Public GraphPFN 내부 대치 상태 갱신) [eval-protocol] Joint imputation의 실행 가능성과 반복 피드백의 예측 가치를 구분한다.

- **JIMP-L02** (Public GraphPFN 내부 대치 상태 갱신) [eval-protocol] FP16 실행 보완을 새 loss·아키텍처 개선과 구분하고 성공 optimizer update 수를 맞춘다.

- **JR-L01** (초기 JR-PFN과 decoder 표현력) [observation-mask] Positive-only diffusion의 구조적 불가능성은 loss로 고칠 수 없었다.

- **JR-L02** (초기 JR-PFN과 decoder 표현력) [eval-protocol] 이미 해결한 중간 병목을 현재 미해결 문제로 다시 제안하지 않는다.
  - 양의 diffusion 표현력 문제는 contrastive decoder로 전환했다. 이후 EAJ/R1의 경쟁력 실패는 별개의 문제이며 기존 LLBP 항목에 보존한다.

  - R1−R0, R1−Constant는 성공이었지만 Grid6과의 비교에서 승격 근거가 사라졌다.
- **LLBP-L6** (Learned-Likelihood BP / EAJ) [eval-protocol, model-based-baseline] 강한 기준선(이미 존재하는 명시적 grid 등)과의 품질·비용 비교를 재학습·확장 실험보다 먼저 한다.

### 아직 안 한 것 — 실패로 세지 않음
- **CFB-U01** (Context-conditioned feature belief GraphPFN 설계 검토) [observation-mask] Context labels에 조건화한 joint feature law와 shared observed encoder/particle suffix를 학습한 GraphPFN
  - 최종 목표와 loss/계산 공유의 설계만 정리했다. 새 neural model 학습, random-fill null control, label-blind 대비, CE-only 대비 coherence의 독립 이득, latency·memory 및 실제 graph/schema 전이는 아직 실행하지 않았다.
- **DFACT-U01** (Disjoint feature–label factor PFN pilot) [observation-mask] 새로운 feature law·semantic schema·real graph·99.5% missing으로의 확장
  - 이번 실행은12 nodes·binary classes·2 Gaussian features·2 relations다. Context1/2/4는 총 label 수이며 per-class가 아니다. 3/6 observed nodes는75/50% node missing이며99.5% 조건이 아니다. Variable feature count를 표현할 수 있는 코드여도 평가는2 features만 수행했다.
- **REOPEN-U01** (실패 기록과 기존 논문을 연결한 후속 후보 선별) [observation-mask] Label memory와 observed-feature memory를 분리하는 graph PFN
  - TabImpute의 query 상호작용과 Ephris의 전체 노드 feature Gather를 단서로, label 읽기는 C, feature f의 실측값 읽기는 O_f={j:M_jf=1}로 두는 후보. NEXT-U02의 sparse observation 안을 구체화한 것으로, 별개의 발명·학습된 성공으로 세지 않는다.
