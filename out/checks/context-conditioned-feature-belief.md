# 아이디어 점검 (2026-11-02)

> Synthetic graph prior에서 context labels에 조건화한 joint feature law를 학습하고 observed encoder와 hypothesis suffix를 공유한다. Martingale coherence는 알려진 학습 원리로 취급하며, valid conditional sampling·feature-law 식별·stochastic coarse estimator의 독립 replica·동일 비용 대조를 검증한다. 새 학습은 아직 미실행이다.

태그: graph-structure-use, inference-cost, observation-mask, uncertainty / 키워드: context-conditioned feature posterior, martingale consistency, shared encoder, conditional refinement

## 1. 차별점을 정리해야 할 선행연구
같은 축을 이미 강점으로 내세운 방법 논문이에요. 기각 사유가 아니라, 무엇이 다른지 한 줄로 써둘 대상입니다.

- **Chronos-2** [inference-cost, uncertainty] quantile을 21개(0.01~0.99)로 촘촘히 내서 극단 구간까지 다룬다. A10G GPU 한 장에서 초당 약 300개 series를 처리하고, 28M짜리 Small 모델은 약 2배 빠르면서 GIFT-Eval skill이 약 1점만 낮다. context를 8,192로 늘린 2단계 학습은 고주파 데이터에서 특히 도움이 되었다.
- **DeepProbLog** [uncertainty] 지각 결과를 하나로 확정하지 않고, 여러 후보의 확률을 논리 추론에 전파할 수 있다.
- **GraphPFN** [graph-structure-use] Hand-crafted graph feature(Laplacian PE, PageRank, 이웃 평균 등)에 기대지 않고, 모델 안에서 adjacency-masked attention으로 message passing을 직접 학습한다. 그 결과 ICL만으로도 G2T-FM·TAG와 튜닝된 GNN보다 평균 rank가 높고, 무거운 전처리도 필요 없다.
- **GraphPFN** [inference-cost] LimiX에서 warm-start하고 adapter만 학습하므로 사전학습이 A100 8장으로 약 36시간에 끝난다. ICL 추론 시간은 GCN을 처음부터 학습하는 것과 같은 자릿수이고, 하이퍼파라미터 탐색이 필요 없다.
- **LoGIC** [inference-cost] 예산을 정한 context만으로 full-context 정확도를 유지하면서 peak 메모리를 크게 줄인다. GraphPFN 기준 artnet-exp에서 full graph 추론은 51.86 AP에 19.59GB였는데, LoGIC은 52.06 AP에 8.24GB였다. TabPFNv2 기준 tolokers-2에서도 4.10GB가 2.20GB로 줄었고 AP는 오히려 조금 올랐다.
- **LoGIC** [inference-cost] Backbone을 재학습하지 않는 추론 시점 인터페이스라서, pure-tabular backbone(G2T featurization + TabPFNv2·LimiX)과 adapter backbone(GraphPFN)에 같은 방식으로 붙는다. 정식화 자체가 full-context tabular 추론, per-query retrieval, full-graph 추론을 특수한 경우로 포함하므로 기존 protocol과의 관계도 분명하다.
- **LoGIC** [graph-structure-use] Full context가 항상 최선은 아니라는 점을 보였다. TabPFNv2로 twitch-views에서 LoGIC은 73.25 R²로 published full-context 70.21보다 3점 높았고, LimiX에서도 74.15 대 71.31이었다. 어떤 labeled 노드를 넣느냐가 그 자체로 성능을 움직이는 설계 변수라는 뜻이다.
- **LoGIC** [graph-structure-use] Label 예산과 구조 예산을 분리한 halo 설계가 adapter backbone에서 효과를 보였다. tolokers-2에서 PPR context(k=4096)만 넣으면 54.20 AP였지만, label을 가린 1-hop halo를 더하자 61.09 AP로 올라 full-graph 기준치(61.29)에 거의 도달했다.
- **MaM** [inference-cost] 관측 subset의 marginal probability를 직접 근사해 반복 conditional 평가의 비용을 줄인다.
- **MaM** [observation-mask] Marginal과 conditional을 연결하는 self-consistency를 명시한다.
- **MCSSL** [observation-mask, uncertainty] 정보 증가에 따른 예측 갱신을 허용하면서 평균의 일관성을 제약한다.
- **Moirai-MoE** [inference-cost] 활성 parameter 수를 Moirai와 맞춰서 추론 시간이 거의 같다. 같은 설정에서 Moirai-MoE-Small과 Base는 273초와 370초로 Moirai-Small과 Base의 264초, 358초와 비슷했다. patch 크기 1로 autoregressive 예측하는 Chronos(551~2,780초)보다는 훨씬 빨랐다.
- **Moirai-MoE** [uncertainty] 학습에 쓰지 않은 10개 데이터셋 zero-shot 평가에서 Base가 CRPS와 MASE 평균 모두 최고였고, 평가 데이터 일부가 사전학습에 들어간 TimesFM, Chronos, Time-MoE보다도 나았다. Small도 모든 크기의 Moirai보다 CRPS가 3~14%, MASE가 8~16% 좋았다. point 예측 지표 외에 PICP, QICE 같은 구간 coverage 지표까지 함께 보고했다.
- **Moirai-MoE** [inference-cost] next-token prediction으로 학습 목표를 바꿔 학습 효율을 높였다. 50k step 학습이 masked filling 100k step과 비슷한 성능을 냈고, Moirai-MoE-Small은 25k step만에 125k step 학습한 Moirai-Small을 넘었다.
- **Moirai** [uncertainty] mixture distribution 출력으로 양수 count, 오른쪽으로 치우친 분포, 확신이 높은 구간을 한 head에서 다룬다. Student-t 하나로 바꾸면 Monash 정규화 MAE가 0.655에서 0.740으로 나빠졌고, peak 구간에서 대칭 분포가 부적절한 예측 구간을 내는 사례도 보였다.
- **Moirai** [inference-cost] 학습 때 window 길이와 예측 비율을 무작위로 뽑아서 하나의 모델이 임의의 context·prediction length를 처리한다. masked encoder라 horizon 전체를 forward 한 번으로 내므로 autoregressive decoding의 누적 오차와 반복 비용이 없다. ETTm1, Electricity, Weather에서는 context를 수천 step까지 늘릴수록 오차가 줄었는데, 기존 Transformer 예측 모델에서는 잘 나타나지 않던 성질이다.
- **Moirai** [inference-cost] multi patch size와 sequence packing이라는 설계 선택의 효과를 ablation으로 보였다. multi patch size를 없애고 patch를 32로 고정하면 Monash 정규화 MAE가 0.655에서 1.156까지 나빠졌다. 길이가 제각각인 sample을 packing으로 묶어 padding 비율을 61%에서 0.4% 수준으로 낮췄고, 같은 compute에서 성능이 16% 좋아졌다.
- **NodePFN** [graph-structure-use] cSBM의 homophily를 넓게 샘플링해 heterophily 쪽도 prior에 넣었다. 그 결과 heterophilous 그룹 평균에서 GCN보다 6%p 이상 높았다.
- **NodePFN** [graph-structure-use] attention branch와 GCN branch를 층마다 병렬로 두는 단순한 dual-branch 구조로 그래프 구조를 PFN에 넣었다. MPNN branch를 빼면 Cora와 Wisconsin에서 accuracy가 크게 떨어져, 구조 branch의 기여가 ablation으로 확인된다.
- **NodePFN** [inference-cost] 약 29M parameter 모델을 단일 GPU에서 약 6 GPU-hour로 사전학습할 만큼 가볍고, 추론은 forward pass 한 번이다.
- **PEMix** [graph-structure-use, observation-mask, uncertainty] Clustered missingness의 전파 경계 병목을 분석하고, 관측값 전파에 의존하지 않는 구조 조건부 feature distribution을 제시한다.
- **PEMix** [observation-mask] Fully missing node에서도 PE-conditioned mixture responsibility가 남아 노드별 대치를 구분할 수 있다.
- **Scallop** [inference-cost] Top-k proof 등으로 계산량을 조절하며, MNIST-R에서 DeepProbLog 2021 확장판 대비 학습 시간을 줄였다.
- **Sundial** [uncertainty] flow matching 기반 TimeFlow Loss로 분포 형태를 미리 정하지 않고 연속값에서 바로 생성형 확률 예측을 한다. 이산 tokenization의 out-of-vocabulary 문제와 거친 예측 구간을 피하고, 평균이나 quantile 말고도 sample에서 임의의 통계량을 추정할 수 있다.
- **Sundial** [inference-cost] 추론 비용을 줄이는 설계가 촘촘하다. multi-patch prediction으로 decoding step을 줄였고, KV cache와 FlashAttention으로 메모리를 14.8%, 추론 시간을 43.6% 줄였다. 20개 sample을 각각 50 step으로 만들어도 CPU에서 1초 남짓이며, FEV에서는 Chronos보다 약 35배 빠르다고 보고한다.
- **Sundial** [uncertainty] sample 개수와 flow-matching step 수를 추론 시에 조절해서 재학습 없이 정확도와 속도를 맞바꿀 수 있다. FEV에 한 번 fine-tuning하면 zero-shot보다 더 좋아지고, 같은 데이터로 처음부터 학습한 모델보다는 확실히 좋아 사전학습 지식이 전이됨을 보였다.
- **Time-MoE** [inference-cost] sparse MoE로 시계열 foundation model을 처음 2.4B 파라미터까지 키웠다. 같은 활성 파라미터의 dense 모델과 비교하면 학습 비용은 평균 78%, 추론 비용은 39% 줄었다. ultra 모델도 8GB 미만 VRAM의 소비자용 GPU에서 돌아간다.
- **Time-MoE** [inference-cost] 여러 해상도의 출력 head를 함께 학습해서 긴 horizon을 적은 decoding step으로 만든다. ablation에서 horizon 1짜리 head 하나로만 autoregressive하게 예측하면 MSE가 1.382까지 무너졌지만, 네 head를 쓰면 0.262였고 추론도 가장 빨랐다.
- **TimesFM** [inference-cost] 출력 patch를 입력 patch보다 길게 잡은 설계 덕분에 긴 horizon을 적은 decoding step으로 예측한다. 512 step 예측 ablation에서 출력 patch 128이 32보다 오차가 작았는데, step 수가 16에서 4로 줄어 누적 오차가 줄어든 효과로 해석된다.
- **TimesFM** [inference-cost] 200M 규모의 비교적 작은 모델로 Monash, Darts, ETT에서 zero-shot 성능이 dataset별 supervised 모델과 비슷한 수준에 도달했다. GPT-3 기반 LLMTime보다 Monash에서 10% 이상 좋으면서 추론 비용은 훨씬 작다.
- **TSFM-Interventions** [inference-cost] 표현 분석을 실제 효율 개선으로 연결했다. fine-tuning한 MOMENT에서 중복 block을 모두 잘라내도 장기 예측 성능이 원래 모델과 거의 같았고, 메모리는 절반 넘게 줄었다. ILI에서는 MSE가 3.260에서 2.981로 오히려 좋아졌다. MOMENT-Large에서 block 하나만 잘라도 모델 크기가 11%, 추론 시간이 5% 줄었다.
- **Wander** [graph-structure-use] 구조적 수용 범위를 추론 때 조절할 수 있다. Message passing 기반 GFM은 이 범위가 network 깊이에 고정된다. 서로 떨어진 25×25 grid 5개에 grid마다 label을 2개만 준 GRIDS에서, walk 길이를 4에서 64로 늘리자 정확도가 56.6%에서 96.6%로 올랐다. Labeled 노드를 지나는 walk만 남기면 100%였다. 같은 과제에서 GraphPFN은 23.3%, NodePFN은 26.6%였다. Feature 없는 실제 그래프 4개에서도 Wander는 76.5%로 GraphPFN(60.1%)을 크게 앞섰다.

평가·분석 연구 중 이 축을 다룬 것 (실험 설계·평가 protocol 참고용):
- **FoundTS** [inference-cost] 정확도와 함께 학습·추론 효율을 비교했다. 0.8M 파라미터의 TTM이 훨씬 큰 모델 일부를 앞섰고, 저자들은 현재 TSFM에서 scaling law가 엄밀히 성립하지 않는다고 결론지었다. ROSE와 TTM은 효율과 정확도를 함께 갖췄고, S²IP-LLM은 dataset별 모델보다 느리면서 정확도도 낮았다.
- **GFM-FairEval** [inference-cost] Tuning 시간, 학습 1회, 추론 1회, VRAM을 모델과 데이터셋별로 모두 표에 적었다. 덕분에 'PFN이 이기지만 비싸다'는 결론을 숫자로 확인할 수 있다. 예를 들어 tolokers-2에서 GNN 추론은 0.05초인데 GraphPFN은 6초이고, TAG는 city-reviews에서 추론에 30분 넘게 걸린다.
- **GIFT-Eval** [uncertainty] point 지표만 보지 않고 CRPS로 확률 예측을 평가했다. 모든 점수를 Seasonal Naive 대비 비율로 정규화하고, 97개 조합별 순위를 평균 내서 스케일이 큰 데이터셋 하나가 집계를 지배하지 않게 했다.
- **NodeGround** [inference-cost] 비용을 workflow 단위로 잰다. 튜닝 trial 전체 시간을 포함한 workflow 시간과 peak GPU 메모리를 측정하고, Pareto frontier와 튜닝 예산 1~201개 곡선으로 'GFM이 덜 튜닝한 GNN보다 싸고 좋은가'를 직접 묻는다. 그 결과 구체적인 trade-off가 숫자로 나온다. 예를 들어 50/25/25에서 GraphPFN은 Mean Improvability가 가장 낮았고 모든 supervised 튜닝 궤적보다도 낮았지만, workflow 비용은 데이터셋별 가장 싼 방법의 약 84배(Mean Overhead 약 6.4)였다.
- **NodeGround** [graph-structure-use] 7개 데이터셋 성질로 22개 부분집합을 만들어 '어떤 조건에서 GFM이 지는가'를 진단한다. 예를 들어 GraphPFN은 binary task, high-degree 그래프, 중간 수준 homophily에서는 튜닝된 GCNII·GPRGNN보다 앞서지만, 강한 homophily, 고차원 feature, 심한 불균형 target, 10개 초과 class에서는 뒤진다. 평균 순위 하나로는 보이지 않는 약점을 드러낸다.
- **TSFM-Survey** [uncertainty] objective function을 분류 축으로 따로 세웠다. 같은 architecture라도 MSE, Huber, likelihood 중 무엇으로 학습했는지에 따라 point forecast만 내는지 분포를 내는지가 갈린다는 점을 드러낸다. 저자들은 기존 서베이가 objective가 architecture 선택에 미치는 영향을 거의 다루지 않았다고 지적한다.
- **TSFM-Survey** [uncertainty] Table 2가 15개 모델을 같은 열로 정리해서 모델 선택용 참고표로 쓰기 좋다. 예를 들어 MOMENT와 TimesFM은 결정적 출력, Chronos와 MOIRAI는 확률적 출력, Time-MoE는 point forecast만 낸다는 점을 바로 비교할 수 있다.
- **TSFM-Survey** [uncertainty] 모델별 한계를 한 절에 모았다. TimesFM은 주로 단변량이고 명시적인 확률 예측이 없으며, MOIRAI는 frequency별 patch 크기 대응이 heuristic이고 고차원 시계열로 잘 확장되지 않으며, Lag-Llama는 단변량만 지원한다는 식이다. 한계를 태그로 엮는 이 하네스의 입력으로 바로 쓸 수 있다.

## 2. 동기로 인용할 수 있는 한계
이 아이디어가 겨냥하는 축에서 기존 논문이 약하다고 확인된 지점이에요. 후속 논문·리뷰 지적이 가장 강한 근거입니다.

- **GraphPFN** (후속 논문 지적 — A Fair Evaluation of Graph Foundation Models for Node Property Prediction (2026)) [inference-cost] 후속 재평가에서 GraphPFN은 finetuning 시 10개 GraphLand 데이터셋 모두 1위였지만, 추론 비용과 메모리가 튜닝된 GNN보다 훨씬 컸다. GNN 추론은 1초 미만인데 GraphPFN은 수 초에서 수 분이 걸렸고, 일부 데이터셋에서는 학습 peak 메모리가 80GB GPU 한 장을 넘어 model parallelism이 필요했다. 수백만 노드 규모 데이터셋은 평가 대상 GFM 모두가 처리하지 못해 제외되었다. (GraphPFN 저자 일부가 쓴 논문이다.)
- **GraphPFN** (후속 논문 지적 — LoGIC: Budgeted Context Construction for Node-Level Graph In-Context Learning with Tabular Foundation Models (2026)) [inference-cost] GraphPFN의 adapter 방식은 graph attention이 message passing을 하도록 전체 그래프를 가속기 메모리에 올려 두고, 학습 table 전체를 context로 쓴다고 지적한다. 그래서 peak 메모리가 노드 수뿐 아니라 그래프 크기와 feature 수에 따라 커진다. 이 논문은 GraphPFN checkpoint를 그대로 둔 채 예산을 정한 subgraph context만 구성해도 정확도가 비슷하거나 조금 높게 나온다고 보고한다. 예를 들어 artnet-exp에서 peak 메모리가 약 19.6GB에서 8.2GB로 줄었다.
- **GraphPFN** (후속 논문 지적 — NodeGround: A Node Classification Benchmark in the Graph Foundation Model Era (2026)) [graph-structure-use] 대규모 node classification benchmark에서 GraphPFN은 가장 강한 GFM이었지만, 데이터셋 조건별로 보면 강한 homophily, 고차원 feature, 심하게 불균형한 target에서 튜닝된 GNN(GCNII, GPRGNN)에 뒤졌다. 10개 초과 class task도 불리했다. 라벨을 50%까지 늘려도 고차원 feature·불균형 target·다중 class 약점은 남았다. 저자들은 사전학습 표현을 새 그래프에 적응시키는 능력의 한계로 해석한다.
- **GraphPFN** (후속 논문 지적 — To Learn is to Wander: Learning Across Graphs and Tasks with Random Walks (2026)) [graph-structure-use] GraphPFN 같은 message passing 기반 foundation model은 구조적 수용 범위가 network 깊이에 고정되어 추론 시 조절할 수 없고, 표현력도 표준 message passing 범위에 묶인다고 지적한다. 실제로 node feature가 없는 구조 위주 task에서 GraphPFN은 크게 실패했다(Grids 23.3% vs random-walk 기반 Wander 96.6%).
- **Moirai** (후속 논문 지적 — Moirai 2.0: When Less Is More for Time Series Forecasting (2025)) [uncertainty] 같은 Salesforce 그룹의 후속작이 Moirai의 핵심 설계를 대부분 되돌렸다. masked encoder는 sample 하나당 loss를 한 번만 내고 가려진 일부 token만 loss에 참여해서 데이터 활용이 비효율적이고, 반복 예측 때마다 key-value를 처음부터 다시 계산해야 한다고 지적했다. multi-patch 구성은 frequency 간 학습을 오히려 제약했다고 보고 single patch로 바꿨다. mixture distribution 출력은 실제로는 효과가 덜하고 설계와 최적화를 복잡하게 만들며, NLL이 outlier에서 variance collapse나 불안정한 gradient를 겪을 수 있다며 quantile loss로 대체했다. multivariate 예측과 covariate 지원은 이득이 거의 없었다며 아예 뺐고, 그런 성질을 가진 고품질 데이터가 부족한 탓으로 추정했다.
- **MOMENT** (후속 논문 지적 — TSFM-Bench: A Comprehensive and Unified Benchmark of Foundation Models for Time Series Forecasting (KDD 2025; arXiv 초판 제목 FoundTS)) [inference-cost] 통합 forecasting 벤치마크에서 MOMENT를 channel independence를 가정하는 대표 모델로 분류했다. 변수 간 상관이 강한 데이터셋에서는 channel dependence를 다루는 foundation model보다 뒤처졌고, 특히 Traffic에서 고전했다고 지적했다. runtime과 정확도 양쪽에서 dataset-specific 모델에 밀린다는 평가도 함께 내렸다.
- **MOMENT** (후속 논문 지적 — Foundation Models for Time Series: A Survey (2025)) [uncertainty] MOMENT는 기본 설정에서 단변량 입력만 다루고 확률적 예측을 내지 못한다고 정리했다. 불확실성 추정이 필요한 응용에는 바로 쓰기 어렵다는 뜻이다.
- **MOMENT** (후속 논문 지적 — Exploring Representations and Interventions in Time Series Foundation Models (ICML 2025)) [inference-cost] MOMENT-Large의 layer 간 CKA 유사도를 보면 여러 layer가 거의 같은 표현을 내는 block 구조가 나타났다. 이 중복 block을 잘라내도 장기 예측 성능은 거의 유지되면서 메모리가 크게 줄었다. 385M 파라미터 중 상당 부분이 효율적으로 쓰이지 않는다는 뜻이다. MOMENT 저자 일부가 참여한 후속 분석이다.
- **NodePFN** (후속 논문 지적 — NodeGround: A Node Classification Benchmark in the Graph Foundation Model Era (2026)) [inference-cost] labeled node 사이의 dense self-attention 때문에 큰 그래프에서 추론 비용이 크다고 지적한다. 성능-비용 비교에서 NodePFN은 더 싸면서 더 정확한 방법에 dominate되어 Pareto frontier에 들지 못했고, 잘 튜닝된 supervised 방법보다 성능이 낮았다.
- **Sundial** (후속 논문 지적 — Evaluating Accuracy and Probabilistic Reliability of Zero-Shot Time Series Foundation Models (2026)) [uncertainty] zero-shot TSFM 6개의 80% 예측 구간 보정을 평가했다. Sundial은 context 길이와 상관없이 과신(over-confident)했다. 폴란드 전력망 부하 데이터에서는 interval coverage error가 약 0.45였고, S&P 500 ETF 가격에서는 0.50을 넘겨 목표로 한 가격 변동의 절반을 구간 밖으로 놓쳤다. 같은 평가에서 Chronos-2와 TiRex는 잘 보정되었다. 생성형 sampling이 신뢰할 만한 불확실성을 준다는 Sundial의 핵심 주장과 정면으로 부딪히는 결과다.
- **Time-MoE** (후속 논문 지적 — Sundial: A Family of Highly Capable Time Series Foundation Models (ICML 2025)) [uncertainty] TimesFM, Timer와 함께 Time-MoE를 연속값을 embedding하고 MSE나 quantile loss로 단봉 분포를 맞추는 모델로 분류한다. 예측 분포가 도메인마다 크게 갈리는 상황에서 이런 고정된 prior loss는 mode collapse와 지나치게 매끄러운 예측을 낳고, 예측의 신뢰 수준을 알려주지 못해 의사결정에 쓰기 어렵다고 비판한다. TSLib zero-shot에서 Sundial은 더 적은 파라미터로 Time-MoE 대비 평균 MSE를 7.57% 낮췄다고 보고한다.
- **Time-MoE** (후속 논문 지적 — TimeSqueeze: Dynamic Patching for Efficient Time Series Forecasting (2026)) [inference-cost] Time-MoE 같은 point-wise encoding은 sequence가 길어질수록 확장성이 떨어지며, 이것이 긴 context 사전학습의 병목이라고 지적한다. 이 논문은 Time-MoE의 backbone, Time-300B, 손실을 그대로 두고 tokenizer만 SSM 기반 dynamic patching으로 바꿨다. 그 결과 학습이 최대 20배 빠르고 사전학습 데이터 효율이 8배 높다고 보고한다.
- **TimesFM** (후속 논문 지적 — Unified Training of Universal Time Series Forecasting Transformers (Moirai, 2024)) [uncertainty] 사전학습 데이터가 Google Trends와 Wiki pageview에 크게 의존해서 시계열이 나온 도메인의 다양성이 부족하다고 지적한다. 비교표에서도 TimesFM을 any-variate zero-shot과 probabilistic forecasting을 지원하지 않는 모델로 분류한다.
- **TimesFM** (후속 논문 지적 — Sundial: A Family of Highly Capable Time Series Foundation Models (2025)) [uncertainty] TimesFM처럼 MSE나 quantile loss로 단봉(unimodal) 분포를 맞추는 모델은 도메인마다 크게 다른 예측 분포 앞에서 mode collapse와 지나치게 매끄러운 예측을 낳는다고 지적한다. 예측의 신뢰 수준을 알려주지 못해 의사결정용으로는 신뢰도가 떨어진다는 점도 함께 든다.
- **DreamCoder** (저자 인정) [uncertainty] Discussion은 명확한 기호 해로 설명되는 문제를 중심으로 평가했으며, 현실의 광범위한 noise·uncertainty 처리는 향후 과제로 남긴다.
- **DreamCoder** (저자 인정) [inference-cost] 훈련에는 상당한 탐색 자원이 필요하다. 본문은 보통 20–100 CPU에서 약 하루, 최소 Lisp primitive 실험에는 64 CPU에서 약 5일을 보고한다.
- **FoundTS** (저자 인정) [inference-cost] 일부 TSFM은 full-shot 학습이 너무 오래 걸려 full-shot 평가를 일부 모델에만 했다고 저자들이 밝혔다. 학습 시간을 최대 10시간으로 제한했고 이를 넘긴 모델은 결과표에서 빠져 있다. 단기 예측 데이터셋에 적용할 수 없는 모델도 있었다.
- **LoGIC** (저자 인정) [inference-cost] 예산은 backbone 한 번의 입력 크기를 묶을 뿐 전체 작업량을 묶지 않는다. Query 묶음 수에 비례해 runtime이 늘어나며, tolokers-2의 TabPFNv2 실행처럼 full context보다 느린 경우도 있었다(7.66초 대 6.84초).
- **LoGIC** (저자 인정) [graph-structure-use] Halo는 1-hop만 쓰고, 1-hop 이웃이 상한을 넘으면 uniform sampling으로 근사한다. Adapter가 여러 block에 걸쳐 만드는 다중 hop 수용 영역과 맞춘 halo 정책은 향후 과제로 남았다.
- **MaM** (저자 인정) [uncertainty] Self-consistency가 근사적이면 marginal 비율로 만든 conditional이 정확히 정규화되지 않아 별도 정규화가 필요하다고 §3에서 밝힌다.
- **MCSSL** (저자 인정) [inference-cost] Refinement mechanism의 품질에 의존하며 architecture·scale과의 상호작용이 미해결이다(§6).
- **Moirai-MoE** (저자 인정) [inference-cost] decoder-only 구조라 autoregressive 추론이 느리다는 점을 저자들이 한계로 들었다. quantization, pruning, KV caching을 향후 과제로 제시했지만, 새 token이 생길 때마다 instance normalization 통계를 다시 계산해야 해서 cache한 hidden state가 무효가 되는 문제가 있다고 스스로 지적했다.
- **Moirai-MoE** (저자 인정) [inference-cost] Monash 추론에서 거의 선택되지 않는 expert가 있다고 인정했다. 이런 expert를 잘라 내 추론 효율을 높이는 것은 향후 과제로 남겼다.
- **Moirai-MoE** (저자 인정) [inference-cost] 계산 자원 요구가 너무 커서 Large 모델은 제시하지 않았다고 밝혔다. 그래서 MoE 구조가 Moirai-Large(310M) 이상의 규모에서도 같은 이득을 주는지는 확인되지 않았다.
- **PEMix** (저자 인정) [uncertainty] Diagonal covariance가 주 모델링 한계라고 저자가 명시한다(Appendix E).
- **Scallop** (저자 인정) [inference-cost] Top-k proof의 k를 늘리면 Boolean formula와 weighted model counting 비용이 커져 runtime이 급증한다.
- **Scallop** (저자 인정) [uncertainty] 고급 statistical sampling과 generative modeling은 아직 지원하지 않으며 향후 과제로 남겼다.
- **Sundial** (저자 인정) [inference-cost, uncertainty] Gaussian noise에서 시작하는 단순한 sampling만 썼기 때문에 sampling 전략과 frequency normalization 같은 후처리에 개선 여지가 크다고 저자들이 밝힌다. sample과 step을 늘릴수록 지표가 좋아지므로, 좋은 확률 예측을 얻으려면 추론 시간을 더 써야 하는 trade-off가 있다.
- **TimesFM** (저자 인정) [uncertainty] MSE로 학습한 point forecast가 기본이다. quantile head나 likelihood 출력으로 확률 예측을 붙이는 것은 쉽다고 하지만 이번 연구의 초점이 아니었다고 인정한다. 사용자가 예측을 조정할 수 있는 수단이 사실상 context 길이 하나뿐이라는 점도 저자들이 직접 언급한다.
- **Wander** (저자 인정) [inference-cost] Walk 예산이 크고 sampling을 반복할수록 추론 비용이 커진다. 예산을 줄이면 재학습 없이 빨라지지만 예측 성능이 떨어질 수 있다. 더 효율적이고 적응적인 sampling 전략은 향후 과제로 남았다.
- **DeepProbLog** (조사자 판단) [inference-cost] [analyst] 추론은 grounding과 SDD compilation에 의존하므로, 최종 추론기를 neural network만으로 대체한 것은 아니다. 대규모화 비용은 별도 평가가 필요하다.
- **GFM-FairEval** (조사자 판단) [inference-cost] [analyst] 비용 논증이 정성적이다. GNN은 100 trial, GraphPFN finetuning은 learning rate 10개만 탐색한 상태에서 tuning 시간을 비교한다(예: city-reviews에서 1.08일 대 1.88일). 같은 compute 예산에서 GNN을 덜 튜닝했을 때 성능이 어떤지는 보여주지 않는다. NodeGround의 budget curve 분석에서는 10/10/80 split에서 부분 튜닝한 supervised 방법이 비용 대비 성능 frontier에서 GraphPFN을 앞질렀다.
- **MCSSL** (조사자 판단) [graph-structure-use] [analyst] GraphPFN·새 graph/schema의 zero-shot 성과는 검증하지 않았다.
- **Sundial** (조사자 판단) [uncertainty] [analyst] TimeFlow Loss의 point 예측 이득은 작다. 같은 backbone과 데이터에서 MSE loss로 바꾸면 TSLib 6개 평균 MSE가 0.290에서 0.296으로 나빠질 뿐이고, ETTh1(0.404 대 0.411)과 Weather(0.231 대 0.234)에서는 오히려 MSE loss가 더 좋았다. mode collapse 주장은 주로 정성적 예시 그림에 기대고, 예측 구간 품질은 집계된 CRPS·WQL로만 보였다. 이후 독립 평가에서 과신 문제가 나온 것을 보면, 분포를 미리 정하지 않는다는 것과 보정이 잘 된다는 것은 별개의 문제다.
- **TSFM-Interventions** (조사자 판단) [inference-cost] [analyst] CKA로 중복이라고 판정한 layer가 zero-shot에서는 기능적으로 중복이 아니었다. 모든 block을 잘라낸 Chronos-Large는 ETTh에서 MASE가 0.776에서 1.093으로, ercot에서 0.627에서 1.281로 나빠졌다. MOMENT zero-shot imputation도 ETTh1 MSE가 0.371에서 0.673으로, Electricity에서 0.250에서 0.819로 나빠졌다. pruning의 이득은 사실상 fine-tuning을 전제로 할 때만 확인되었다. block 위치도 눈으로 정했고, 제안한 자동화 알고리즘은 평가하지 않았다.
- **Wander** (조사자 판단) [graph-structure-use] [analyst] 구조 task에서의 큰 우위와 달리, feature가 있는 실제 node classification에서는 GraphPFN 대비 우위가 평균 1.65점으로 작다. 14개 데이터셋 계열 중 5개(Airports, Wiki filt., Actor, Roman Empire, HM Cat.)에서는 GraphPFN이 앞섰다. 튜닝된 GCN과의 격차도 Roman Empire(79.6 대 65.4)와 HM Cat.(66.4 대 48.7)에서 컸다. 극적인 수치(GRIDS 96.6%)는 long-range 전파가 필요하도록 설계된 synthetic 과제와 feature 없는 그래프에서 나온 것이다.
- **Wander** (조사자 판단) [inference-cost] [analyst] 라벨 불균형과 그래프 규모 쪽은 검증되지 않았다. Context는 모든 labeled 노드이고 그 라벨 분포에 대한 분석이 없으며, GRIDS는 class마다 label 2개로 구성상 균형이다. 입력이 관측 그래프 전체인데도 본문에는 runtime·peak 메모리 수치가 없고(부록으로 넘김), 평가는 Pokec 100k 같은 중간 규모 그래프까지다.

## 4. 내 연구에서 이미 확인한 것
### 이미 닫은 갈래 — 같은 가설을 이름만 바꿔 반복하는 건 아닌지 확인
- **BIND-F01** (Common-context witness 고정 곱셈) [graph-structure-use] Class pooling 전 context identity를 보존해 곱하면 실제 graph에서 좋아진다.
  - 판정: 고정 common-witness product 중단. k20 pooling-before-product: ACM76.390% vs uniform LP85.555%, IMDB28.311% vs35.413%. IMDB k20 test row 약96.1%는 공통 seed support가0이었다.
  - 닫은 범위: 현재 모든 relation이 같은 context witness를 가져야 하는 고정 곱셈
  - 닫지 않은 것: Task별 variable binding·논리 연산을 추론하는 일반 executor는 별개다.

  - 닫지 않은 것: joint 표현 자체의 장점(약한 head 대비)은 있었다.

  - 재검토 조건: 강한 classical update의 품질을 유지하며 전체 branch/evidence 비용을 줄이는 연산이 나올 때.
  - 기준선 / 최소 재검증: Constant+role-update, exact-product, Joint Grid6/81 / Posterior 추정만의 시간과 shared BP를 포함한 end-to-end 품질·비용을 분리한다.

- **CFB-L01** (Context-conditioned feature belief GraphPFN 설계 검토) [uncertainty] 관측 refinement의 martingale coherence와 효율적 marginalization 자체는 선행 원리다.
  - MCSSL(2026)의 §3–4가 관측 refinement의 평균 일관성과 two-sample estimator를 다룬다. MaM(ICML2024)은 marginalization self-consistency와 arbitrary marginal 직접 근사를 다룬다. GraphPFN에 해당 loss를 더했다는 사실만으로 새 원리를 주장하지 않는다.
- **CFB-L02** (Context-conditioned feature belief GraphPFN 설계 검토) [uncertainty] 관측 전 예측도 Monte Carlo 평균이면 coarse–refined 두 replica 전체를 독립화해야 하는 경우가 있다.
  - 정확한 scalar 예시에서 올바른 tower squared residual은0, 한 refinement에 직접 맞춘 기대 penalty는0.1024다. 두 독립 refinement를 써도 분산0.01인 coarse estimate를 공용하면 기대 penalty0.01이 남는다. Coarse/refined replica 전체를 독립화하면 약8.7e-19다. 이는 수학 예시이고 GraphPFN 성능 수치가 아니다.
- **CFB-L03** (Context-conditioned feature belief GraphPFN 설계 검토) [uncertainty] Query CE와 coherence만으로 feature 가설의 의미가 식별되지는 않는다.
  - Decoder가 가설을 무시해도 관측 입력의 predictive distribution을 직접 표현할 수 있다. 또한 feature 확률[.1,.2,.3,.4]와[.14,.1,.36,.4]는 label probabilities[.1,.4,.6,.9]에서 모두 평균.63을 준다. 이 coarse/full-reveal 예시에서는 Bayes CE와 coherence가 같아도 feature law가 다르다. 임의의 틀린 q와 모든 refinement에서 성립한다는 주장은 아니다.
- **FMARG-L01** (Frozen GraphPFN joint feature-completion marginalization) [observation-mask, uncertainty] 분포형 input을 적용한 frozen 연산의 성과와 Bayesian posterior·새 학습법을 구분한다.
  - Completion law는 observed-only RMS 좌표의 Gaussian surrogate이며 context labels에는 조건화하지 않는다. PFN은 zero+mask로 학습했던 checkpoint다. PCFI/native-NaN도 같은 checkpoint의 입력 대조이며 각 입력으로 별도 재학습한 모델 성과가 아니다. Point와 sampling 모두 동일4회 PFN forward의 확률을 평균했다.
- **FMARG-L02** (Frozen GraphPFN joint feature-completion marginalization) [graph-structure-use, uncertainty] 노드 간 covariance의 진단은 per-cell variance와 일반 ensemble 효과를 통제한다.
  - Joint와 diagonal에 같은 rho draws·조건부 평균·대각 분산·standard normal draws를 주고 rho 내 off-diagonal covariance만 바꿨다. 두 arm 모두 rho는 graph 공유다. 관측값 clamp·conditional moment node permutation·12000-draw covariance sanity를 확인했다. 이것이 새 정보나 method superiority를 입증하지는 않는다.
- **HET-L02** (Native heterogeneous 입력·기존 relational FM 대조) [observation-mask] 미리 집계된 helper feature를 독립 native 관측값으로 취급하지 않는다.
  - ACM/IMDB helper feature는 target feature에서 파생된 집계일 수 있음을 확인했다. DBLP는 서로 다른 native source block으로 별도 처리했다.
- **JIMP-L01** (Public GraphPFN 내부 대치 상태 갱신) [graph-structure-use] Joint imputation의 실행 가능성과 반복 피드백의 예측 가치를 구분한다.
  - 실제 공개 GraphPFN의 feature-pair token 구조를 유지했다. 관측값 clamp, 원래 mask 유지, refiner/encoder gradient, 노드 순열, 동일 Frontend/Interleaved 초기화·파라미터·schedule, frozen weights 보존과 성공 update192회를 검사했다. 이 검사는 구현 연결성을 보여주며 메소드 우수성의 증거는 아니다.
- **JIMP-L03** (Public GraphPFN 내부 대치 상태 갱신) [graph-structure-use] 피드백 제거 intervention은 FP16 수치 순서를 맞춰 해석하고, 별도 재학습 대조와 구분한다.
  - No-feedback 대조의 h+new−old를 h+(new−old)로 묶어 cancellation을 보완하고, 동일 process의 standard와 다시 짝지었다. Full-observed96건의 차이는 정확히0, 별도 process replay의 최대 확률 차이는0.00246981이었다. 보정된 Uniform의 standard−no-feedback NLL은+0.00306 CI[+0.00063,+0.00581]로 feedback이 더 나빴다. Clustered와 k1의 CI는0 포함. 학습·주 예측·checkpoint를 바꾸지 않았다.
- **JR-L01** (초기 JR-PFN과 decoder 표현력) [graph-structure-use, observation-mask] Positive-only diffusion의 구조적 불가능성은 loss로 고칠 수 없었다.
  - Context label이 모두 A일 때 당시 decoder는 모든 query에서 p(A)≥0.5. Exact teacher는 nonedge로 반대 class를 지지할 수 있었다. 이후 contrastive/BP decoder가 이 제한을 넘었다.
- **LLBP-L0** (Learned-Likelihood BP / EAJ) [graph-structure-use] Teacher를 정확하게 주는 것과 decoder가 그 target을 표현할 수 있는 것은 다르다.
  - 양의 relation weight와 normalization을 쓰는 label diffusion은 context가 전부 클래스 a이면 모든 query에서 p(a) ≥ 1/2를 유지한다. Nonedge로 반대 클래스를 지지하는 exact SBM teacher를 표현할 수 없었고, 이후 decoder 자체를 바꾸는 방향으로 이동했다.
- **LLBP-L4** (Learned-Likelihood BP / EAJ) [inference-cost] Neural amortization이나 branch 수 감소가 곧 wall-clock 우위는 아니다.
  - EAJ에서는 공통 BP 계산이 비용을 지배했고, R1은 병렬 Grid6과 latency가 비슷했다.
- **OBS-L01** (Observation-aware subgraph policy) [inference-cost] 학습 정책의 선택 단계 속도를 end-to-end 우위로 승격하지 않는다.
  - Matched budget64 selection1.76ms vs Paths13.73ms지만 PCFI+forward 포함 약146.82/155.90ms. Global statistics와 정책학습 비용은 이 합계 밖이다.
- **ROLE-L01** (Plain relation adaptation과 CRR 제안 철회) [graph-structure-use] Plain이 전역 relation utility 적응을 못한다는 전제로 새 router를 정당화하지 않는다.
  - 공유 relation MLP에 relation-ID embedding이 없고, context 통계를 따라 역할 교환에 적응했다. Conflict end-to-end는 약2.09%p 하락해 완전 robustness는 아니다.
- **ROLE-L02** (Plain relation adaptation과 CRR 제안 철회) [graph-structure-use, uncertainty] k=1의 centered label-alignment 통계에는 식별 한계가 있다.
  - 클래스당 context 하나면 서로 다른 class centered one-hot 내적은 모두 −1/C다. 이 통계만 복잡하게 인코딩해도 새 정보가 생기지 않는다. 재배선 경로 품질 차이도 함께 고려해야 한다.
- **REG-L01** (Reference-regret prior curriculum) [observation-mask] Singleton observed feature centering은 입력 정보를 없앨 수 있다.
  - Test99.5% whole-node에서 PCFI input 전체가0인 episode는 uniform20/32, clustered32/32. 관측 행0~1개에서 centering 손실을 직접 확인했다.
- **EVID-L01** (Relation-wise Evidence Head) [uncertainty] 확률 점수 개선을 relation 출처의 새 정보나 accuracy 개선으로 치환하지 않는다.
  - Conflict NLL0.5320→0.3585, Brier0.2905→0.2044; NLL 개선의 산술90.5%는 Mean에서도 나타났다. Confidence63.99→84.31%였다.
- **SRC-L01** (출처 중첩·공유 보간 오차 attention) [uncertainty] 추가 사전학습의 효과를 오차 보정 모듈 효과로 치환하지 않는다.
  - Initial 대비 accuracy는 올랐지만 matched continuation 대비 증분은 약0.03%p였다. Balanced accuracy와 macro-F1은 initial 대비 하락했다.

### 아직 안 한 것 — 실패로 세지 않음
