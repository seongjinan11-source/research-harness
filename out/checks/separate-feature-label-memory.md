# 아이디어 점검 (2026-11-02)

> Label memory는 context C만, feature memory는 feature별 실제 관측 집합 O_f를 사용한다. 기본 LimiX attention의 context-only key/value 제한과 graph adapter의 기존 접근을 구분해 검증한다. NEXT-U02의 구체화이며 all-node attention과 observed-only memory를 같은 투영·학습 예산으로 비교한다. TabImpute/Ephris의 기존 연산을 새 발명이라고 주장하지 않는다. 새 학습은 미실행이다.

태그: context-scale, graph-structure-use, observation-mask, tokenization / 키워드: feature memory, label context, query query attention, observed key value, Ephris, TabImpute

## 1. 차별점을 정리해야 할 선행연구
같은 축을 이미 강점으로 내세운 방법 논문이에요. 기각 사유가 아니라, 무엇이 다른지 한 줄로 써둘 대상입니다.

- **Chronos-2** [context-scale] group attention은 group 마스크만으로 섞을 series를 정하고 순서를 가정하지 않으므로 변수 수가 몇 개든 같은 모델로 처리한다. 메모리는 변수 수에 선형으로 늘어난다고 보고하는데, 이는 일부 baseline(COSMIC, Moirai-1.0)의 제곱 증가와 대비된다.
- **Ephris** [context-scale, graph-structure-use, tokenization] Section 3.1과 Appendix B의 feature별 Gather는 context와 query 노드를 모두 사용한다. Context-label embedding도 압축 전 scalar token에 제공하므로, feature memory를 label-context 노드에만 한정하지 않는 직접적인 선행 대조다.
- **GraphPFN** [graph-structure-use] Hand-crafted graph feature(Laplacian PE, PageRank, 이웃 평균 등)에 기대지 않고, 모델 안에서 adjacency-masked attention으로 message passing을 직접 학습한다. 그 결과 ICL만으로도 G2T-FM·TAG와 튜닝된 GNN보다 평균 rank가 높고, 무거운 전처리도 필요 없다.
- **GSPN** [observation-mask] 숫자 대치나 여러 completion forward 없이 모델 내 partial-evidence 추론을 제공한다.
- **LoGIC** [context-scale] 예산을 정한 context만으로 full-context 정확도를 유지하면서 peak 메모리를 크게 줄인다. GraphPFN 기준 artnet-exp에서 full graph 추론은 51.86 AP에 19.59GB였는데, LoGIC은 52.06 AP에 8.24GB였다. TabPFNv2 기준 tolokers-2에서도 4.10GB가 2.20GB로 줄었고 AP는 오히려 조금 올랐다.
- **LoGIC** [graph-structure-use] Full context가 항상 최선은 아니라는 점을 보였다. TabPFNv2로 twitch-views에서 LoGIC은 73.25 R²로 published full-context 70.21보다 3점 높았고, LimiX에서도 74.15 대 71.31이었다. 어떤 labeled 노드를 넣느냐가 그 자체로 성능을 움직이는 설계 변수라는 뜻이다.
- **LoGIC** [context-scale, graph-structure-use] Label 예산과 구조 예산을 분리한 halo 설계가 adapter backbone에서 효과를 보였다. tolokers-2에서 PPR context(k=4096)만 넣으면 54.20 AP였지만, label을 가린 1-hop halo를 더하자 61.09 AP로 올라 full-graph 기준치(61.29)에 거의 도달했다.
- **MaM** [observation-mask] Marginal과 conditional을 연결하는 self-consistency를 명시한다.
- **MCSSL** [observation-mask] 정보 증가에 따른 예측 갱신을 허용하면서 평균의 일관성을 제약한다.
- **Moirai-MoE** [tokenization] frequency별 projection 없이 단일 projection과 MoE로 token 단위 specialization을 데이터가 정하게 했다. Monash 29개 데이터셋에서 Small이 같은 규모의 Moirai-Small보다 17%, 더 큰 Moirai-Base와 Moirai-Large보다 각각 8%, 7% 좋았고, Moirai가 넘지 못했던 Chronos도 앞섰다.
- **Moirai** [tokenization] multi patch size와 sequence packing이라는 설계 선택의 효과를 ablation으로 보였다. multi patch size를 없애고 patch를 32로 고정하면 Monash 정규화 MAE가 0.655에서 1.156까지 나빠졌다. 길이가 제각각인 sample을 packing으로 묶어 padding 비율을 61%에서 0.4% 수준으로 낮췄고, 같은 compute에서 성능이 16% 좋아졌다.
- **MOMENT** [tokenization] patching, RevIN, 좌측 zero-padding, channel 단위 처리라는 단순한 조합으로 길이·스케일·채널 수가 다른 데이터셋을 한 모델에 넣는다. 데이터셋마다 구조를 바꿀 필요가 없다.
- **NodePFN** [graph-structure-use] cSBM의 homophily를 넓게 샘플링해 heterophily 쪽도 prior에 넣었다. 그 결과 heterophilous 그룹 평균에서 GCN보다 6%p 이상 높았다.
- **NodePFN** [graph-structure-use] attention branch와 GCN branch를 층마다 병렬로 두는 단순한 dual-branch 구조로 그래프 구조를 PFN에 넣었다. MPNN branch를 빼면 Cora와 Wisconsin에서 accuracy가 크게 떨어져, 구조 branch의 기여가 ablation으로 확인된다.
- **PEMix** [graph-structure-use, observation-mask] Clustered missingness의 전파 경계 병목을 분석하고, 관측값 전파에 의존하지 않는 구조 조건부 feature distribution을 제시한다.
- **PEMix** [observation-mask, tokenization] Fully missing node에서도 PE-conditioned mixture responsibility가 남아 노드별 대치를 구분할 수 있다.
- **PFNSeparability** [context-scale] 추가 unlabeled row를 실제 사용하는 matched SemiTabICL 대조를 제시한다.
- **StructuralMissingPFN** [observation-mask] Mask를 포함한 불완전 입력에서 직접 예측하며 explicit posterior sampling과 분류 경로를 구분한다.
- **Sundial** [tokenization] flow matching 기반 TimeFlow Loss로 분포 형태를 미리 정하지 않고 연속값에서 바로 생성형 확률 예측을 한다. 이산 tokenization의 out-of-vocabulary 문제와 거친 예측 구간을 피하고, 평균이나 quantile 말고도 sample에서 임의의 통계량을 추정할 수 있다.
- **TabImpute** [observation-mask, tokenization] 새 table에서 fitting 없이 대치하며 row-column 정보를 cell 단위로 공유한다.
- **TabImpute** [observation-mask, tokenization] Section 3의 architecture는 원래 TabPFN의 query 사이 attention 제한을 제거한다. Missing-entry query가 공유 잠재 구조를 통해 의존할 수 있다는 이유이며, 우리 graph PFN의 성능 개선을 입증한 결과는 아니다.
- **TimesFM** [tokenization] 출력 patch를 입력 patch보다 길게 잡은 설계 덕분에 긴 horizon을 적은 decoding step으로 예측한다. 512 step 예측 ablation에서 출력 patch 128이 32보다 오차가 작았는데, step 수가 16에서 4로 줄어 누적 오차가 줄어든 효과로 해석된다.
- **TimesFM** [tokenization] 첫 patch를 무작위 길이로 masking하는 학습 트릭 하나로, patch 길이의 배수가 아닌 context까지 포함해 임의 길이 입력을 하나의 모델로 처리한다.
- **TSFM-Interventions** [tokenization] concept이 어느 layer와 어느 patch에서 구분되는지 위치를 찾았다. 일정한 시계열과 sinusoid의 구분은 시계열 전체를 봐야 생기고, 증가·감소 trend는 처음과 끝 patch에서 구분되었다. amplitude 차이는 어디서도 뚜렷하게 구분되지 않았는데, 저자들은 입력 정규화가 원인일 수 있다고 해석했다.
- **Wander** [graph-structure-use] 구조적 수용 범위를 추론 때 조절할 수 있다. Message passing 기반 GFM은 이 범위가 network 깊이에 고정된다. 서로 떨어진 25×25 grid 5개에 grid마다 label을 2개만 준 GRIDS에서, walk 길이를 4에서 64로 늘리자 정확도가 56.6%에서 96.6%로 올랐다. Labeled 노드를 지나는 walk만 남기면 100%였다. 같은 과제에서 GraphPFN은 23.3%, NodePFN은 26.6%였다. Feature 없는 실제 그래프 4개에서도 Wander는 76.5%로 GraphPFN(60.1%)을 크게 앞섰다.

평가·분석 연구 중 이 축을 다룬 것 (실험 설계·평가 protocol 참고용):
- **GNNmim** [observation-mask] Dense raw-feature 평가와 결측 mechanism shift를 제공해 sparse benchmark의 정보 손실 문제를 구분한다.
- **NodeGround** [graph-structure-use] 7개 데이터셋 성질로 22개 부분집합을 만들어 '어떤 조건에서 GFM이 지는가'를 진단한다. 예를 들어 GraphPFN은 binary task, high-degree 그래프, 중간 수준 homophily에서는 튜닝된 GCNII·GPRGNN보다 앞서지만, 강한 homophily, 고차원 feature, 심한 불균형 target, 10개 초과 class에서는 뒤진다. 평균 순위 하나로는 보이지 않는 약점을 드러낸다.
- **NodeGround** [context-scale] 라벨 조건을 두 가지로 나눠 PFN 계열의 context 크기 의존성을 보여준다. GraphPFN은 10/10/80에서 6위였다가 50/25/25에서 Elo 3위로 올라간다. 반대로 고차원 feature·심한 불균형 target·10개 초과 class의 약점은 라벨을 늘려도 남는다.
- **TSAD-OneLiners** [tokenization] 복원 기반 점수가 왜 분산으로 무너지는지 메커니즘을 밝혔다. window마다 z-normalization을 하면 점수가 'window 분산 × 정규화된 window의 복원 MSE'로 분해된다. MOMENT의 정규화된 복원 MSE는 이상 포함 여부와 상관없이 약 1.1로 거의 일정해서 분산 항이 점수를 결정한다. Min-Max나 전역 정규화로 바꾸면 분산과의 상관이 줄어드는 ablation으로 원인을 확인했다.
- **TSFM-Survey** [tokenization] Table 2가 15개 모델을 같은 열로 정리해서 모델 선택용 참고표로 쓰기 좋다. 예를 들어 MOMENT와 TimesFM은 결정적 출력, Chronos와 MOIRAI는 확률적 출력, Time-MoE는 point forecast만 낸다는 점을 바로 비교할 수 있다.

## 2. 동기로 인용할 수 있는 한계
이 아이디어가 겨냥하는 축에서 기존 논문이 약하다고 확인된 지점이에요. 후속 논문·리뷰 지적이 가장 강한 근거입니다.

- **GraphPFN** (후속 논문 지적 — LoGIC: Budgeted Context Construction for Node-Level Graph In-Context Learning with Tabular Foundation Models (2026)) [context-scale] GraphPFN의 adapter 방식은 graph attention이 message passing을 하도록 전체 그래프를 가속기 메모리에 올려 두고, 학습 table 전체를 context로 쓴다고 지적한다. 그래서 peak 메모리가 노드 수뿐 아니라 그래프 크기와 feature 수에 따라 커진다. 이 논문은 GraphPFN checkpoint를 그대로 둔 채 예산을 정한 subgraph context만 구성해도 정확도가 비슷하거나 조금 높게 나온다고 보고한다. 예를 들어 artnet-exp에서 peak 메모리가 약 19.6GB에서 8.2GB로 줄었다.
- **GraphPFN** (후속 논문 지적 — NodeGround: A Node Classification Benchmark in the Graph Foundation Model Era (2026)) [graph-structure-use] 대규모 node classification benchmark에서 GraphPFN은 가장 강한 GFM이었지만, 데이터셋 조건별로 보면 강한 homophily, 고차원 feature, 심하게 불균형한 target에서 튜닝된 GNN(GCNII, GPRGNN)에 뒤졌다. 10개 초과 class task도 불리했다. 라벨을 50%까지 늘려도 고차원 feature·불균형 target·다중 class 약점은 남았다. 저자들은 사전학습 표현을 새 그래프에 적응시키는 능력의 한계로 해석한다.
- **GraphPFN** (후속 논문 지적 — To Learn is to Wander: Learning Across Graphs and Tasks with Random Walks (2026)) [graph-structure-use] GraphPFN 같은 message passing 기반 foundation model은 구조적 수용 범위가 network 깊이에 고정되어 추론 시 조절할 수 없고, 표현력도 표준 message passing 범위에 묶인다고 지적한다. 실제로 node feature가 없는 구조 위주 task에서 GraphPFN은 크게 실패했다(Grids 23.3% vs random-walk 기반 Wander 96.6%).
- **Moirai-MoE** (후속 논문 지적 — Seg-MoE: Multi-Resolution Segment-wise Mixture-of-Experts for Time Series Forecasting Transformers (2026)) [tokenization] Moirai-MoE와 Time-MoE가 언어 모델에서 가져온 token 단위 routing을 그대로 쓴다고 비판했다. 시계열에서는 이웃한 time step들이 하나의 국소 구조를 이루는데, token마다 따로 expert를 고르면 그 구조가 여러 expert로 쪼개지고, 고립된 token은 noise나 부분 신호에 휘둘릴 수 있다는 것이 근거다. 대안으로 연속된 segment 단위로 routing하는 MoE를 제안했지만, 본문 결과표에서 Moirai-MoE와 직접 비교하지는 않았다.
- **Moirai-MoE** (후속 논문 지적 — Time Tracker: Mixture-of-Experts-Enhanced Foundation Time Series Forecasting Model with Decoupled Training Pipelines (2025)) [tokenization] Time-MoE와 Moirai-MoE가 token마다 다른 expert를 고르는 방식은 그렇게 해야 하는 동기가 불분명하고, 원래 시계열이 가진 통계적 정보를 무시한다고 비판했다. 대안으로 한 변수 시계열의 token들을 같은 expert에 보내는 series 단위 routing을 제안했다. Moirai-MoE와의 실험 비교는 없다.
- **Moirai** (후속 논문 지적 — Moirai-MoE: Empowering Time Series Foundation Models with Sparse Mixture of Experts (ICML 2025)) [tokenization] Moirai의 frequency별 projection을 사람이 정한 specialization이라고 비판했다. frequency가 달라도 패턴이 비슷하거나 frequency가 같아도 패턴이 전혀 다른 경우가 많아서 frequency는 사전학습 데이터를 묶는 기준으로 믿기 어렵고, 짧은 window 안에서도 분포가 바뀌는 non-stationarity를 frequency 단위로는 담지 못한다는 것이 근거다. 실제로 MoE 모델 안에서 multi-patch 구성을 써 보니 single patch의 가장 나쁜 경우와 비슷한 성능에 그쳤다. Monash에서 Moirai는 Chronos를 넘지 못했다는 점도 적었다.
- **Moirai** (후속 논문 지적 — Moirai 2.0: When Less Is More for Time Series Forecasting (2025)) [tokenization] 같은 Salesforce 그룹의 후속작이 Moirai의 핵심 설계를 대부분 되돌렸다. masked encoder는 sample 하나당 loss를 한 번만 내고 가려진 일부 token만 loss에 참여해서 데이터 활용이 비효율적이고, 반복 예측 때마다 key-value를 처음부터 다시 계산해야 한다고 지적했다. multi-patch 구성은 frequency 간 학습을 오히려 제약했다고 보고 single patch로 바꿨다. mixture distribution 출력은 실제로는 효과가 덜하고 설계와 최적화를 복잡하게 만들며, NLL이 outlier에서 variance collapse나 불안정한 gradient를 겪을 수 있다며 quantile loss로 대체했다. multivariate 예측과 covariate 지원은 이득이 거의 없었다며 아예 뺐고, 그런 성질을 가진 고품질 데이터가 부족한 탓으로 추정했다.
- **NodePFN** (후속 논문 지적 — GraphPFN: A Prior-Data Fitted Graph Foundation Model (2026)) [context-scale] 공식 코드는 training sample을 1,024개 이하로 쓰라고 권장하는데, 표준 split의 benchmark들은 모두 이를 넘는다. 이 조건에서 돌린 NodePFN은 모든 데이터셋에서 GraphPFN에 크게 졌고, GCN·GraphSAGE·GAT·GT보다도 평균 순위가 낮았다. 공식 구현에 fine-tuning 경로가 없어 ICL로만 평가할 수 있었다는 점도 함께 지적됐다.
- **NodePFN** (후속 논문 지적 — NodeGround: A Node Classification Benchmark in the Graph Foundation Model Era (2026)) [context-scale] labeled node 사이의 dense self-attention 때문에 큰 그래프에서 추론 비용이 크다고 지적한다. 성능-비용 비교에서 NodePFN은 더 싸면서 더 정확한 방법에 dominate되어 Pareto frontier에 들지 못했고, 잘 튜닝된 supervised 방법보다 성능이 낮았다.
- **Time-MoE** (후속 논문 지적 — Moirai-MoE: Empowering Time Series Foundation Models with Sparse Mixture of Experts (ICML 2025)) [tokenization] Time-MoE가 기존 gating 함수를 그대로 가져다 썼을 뿐 새로운 gating을 제안하거나 MoE 내부 동작을 분석하지 않았다고 지적한다. point-wise tokenization은 시계열의 의미 단위를 담지 못해 성능을 제한할 수 있다고도 본다. 실제로 사전학습에 쓰이지 않은 10개 데이터셋 zero-shot 평가에서, 누수 데이터셋을 뺀 평균 MASE(seasonal naive 대비 정규화)는 Time-MoE base·large 모두 0.695였다. 이는 Moirai-MoE base(0.611)뿐 아니라 TimesFM(0.640), Chronos-base(0.631), Moirai-large(0.685)보다도 나쁜 값이다. 이 표에서 Electricity와 Solar는 Time-MoE의 사전학습에 포함된 non-zero-shot 데이터셋으로 표시되었다. 다만 Time-MoE는 context를 4,096으로 고정했고 Moirai 계열은 context를 탐색했다.
- **Time-MoE** (후속 논문 지적 — TimeSqueeze: Dynamic Patching for Efficient Time Series Forecasting (2026)) [context-scale, tokenization] Time-MoE 같은 point-wise encoding은 sequence가 길어질수록 확장성이 떨어지며, 이것이 긴 context 사전학습의 병목이라고 지적한다. 이 논문은 Time-MoE의 backbone, Time-300B, 손실을 그대로 두고 tokenizer만 SSM 기반 dynamic patching으로 바꿨다. 그 결과 학습이 최대 20배 빠르고 사전학습 데이터 효율이 8배 높다고 보고한다.
- **TimesFM** (후속 논문 지적 — Moirai-MoE: Empowering Time Series Foundation Models with Sparse Mixture of Experts (2025)) [tokenization] TimesFM이 frequency embedding으로 데이터를 frequency 단위로 구분하는 방식을 사람이 정한 heuristic이라고 비판한다. frequency가 실제 패턴을 잘 대변하지 못하고, non-stationary 시계열에는 frequency 단위 구분이 너무 거칠다는 것이 근거다. 평가에서도 TimesFM의 Monash와 Electricity 결과에 사전학습 데이터 중복 표시를 달았다.
- **GFM-FairEval** (저자 인정) [context-scale] GraphLand의 100만 노드 이상 데이터셋 4개는 평가한 GFM 중 어느 것도 처리하지 못해 제외했다. 따라서 결론은 100만 노드 미만 그래프로 한정된다. 남은 데이터셋에서도 GraphPFN 학습 VRAM이 city-reviews 146.66GB, city-roads-L 145.49GB로 80GB GPU 한 장을 넘어 model parallelism을 써야 했다.
- **GNNmim** (저자 인정) [graph-structure-use] Missing edges, uncertain topology와 missing labels는 범위 밖이라고 저자가 명시한다.
- **GraphPFN** (저자 인정) [context-scale] 구현이 전체 데이터셋(그래프)을 한 번에 처리해야 하므로 메모리 사용이 크고, 아주 큰 그래프로 확장하기 어렵다. 저자들은 TabICL 같은 메모리 효율적 backbone이나 subgraph sampling을 해법 후보로 든다.
- **GraphPFN** (저자 인정) [context-scale] Feature 차원이 높은 text-embedding 데이터셋(amazon-ratings, questions)은 finetuning이 불가능해 PCA로 64차원까지 줄여야 했다. PCA를 쓰면 성능이 크게 떨어지는 pubmed(500차원)는 finetuning 중 메모리 부족이 나서 ICL 결과로 대신 보고했다.
- **GSPN** (저자 인정) [graph-structure-use] Cyclic graph의 전역 joint 대신 locally valid SPN의 composition을 사용한다고 저자가 명시한다.
- **LoGIC** (저자 인정) [context-scale] 약 512 row 아래로 예산을 줄이면 모든 channel의 성능이 크게 떨어진다. 즉 예산을 무한정 줄일 수는 없고, 이 하한은 현재 backbone의 용량에서 온다.
- **LoGIC** (저자 인정) [graph-structure-use] Halo는 1-hop만 쓰고, 1-hop 이웃이 상한을 넘으면 uniform sampling으로 근사한다. Adapter가 여러 block에 걸쳐 만드는 다중 hop 수용 영역과 맞춘 halo 정책은 향후 과제로 남았다.
- **MCSSL** (저자 인정) [tokenization] Latent-space 보장은 encoder가 보존한 정보에 상대적이다(§3.5).
- **Moirai** (저자 인정) [tokenization] frequency마다 patch size를 미리 정해 두는 multi patch size 방식이 다소 heuristic이라고 저자들이 인정했다. 더 유연하고 깔끔한 cross-frequency 학습 방법을 향후 과제로 남겼다.
- **Moirai** (저자 인정) [context-scale] 현재 구조가 고차원 시계열을 제한적으로만 지원한다고 저자들이 밝혔다. 모든 변수를 한 sequence로 펴므로 변수 수만큼 token이 늘어나기 때문이며, Transformer 입력 길이를 효율적으로 늘리는 방법을 해법으로 들었다.
- **MOMENT** (저자 인정) [tokenization] 입력마다 정규화를 하기 때문에 수직 이동(level shift)만 다른 두 시계열을 구분하지 못한다. 저자들이 직접 밝힌 한계다.
- **MOMENT** (저자 인정) [tokenization] sampling frequency 같은 시간 해상도 정보를 모델에 명시적으로 넣지 않았다고 저자들이 밝혔다.
- **NodePFN** (저자 인정) [context-scale] attention 비용이 quadratic이라 큰 그래프에 적용하기 어렵다고 저자들이 인정하고, efficient attention을 future work로 남겼다.
- **Ephris** (조사자 판단) [observation-mask] [analyst] 본문에서 우리의 severe whole-node/clustered feature missing 프로토콜에 대한 성능은 확인하지 못했다.
- **Ephris** (조사자 판단) [graph-structure-use, tokenization] [analyst] Sparse message passing과 synthetic pretraining의 조합만으로 새 방법의 novelty를 주장하기 어려워졌다.
- **MCSSL** (조사자 판단) [graph-structure-use] [analyst] GraphPFN·새 graph/schema의 zero-shot 성과는 검증하지 않았다.
- **Moirai-MoE** (조사자 판단) [tokenization] [analyst] 성능 향상이 MoE에서 왔다는 결론이 ablation으로 충분히 분리되지 않았다. Monash 정규화 MAE로 보면 multi projection 상태에서 dense를 MoE로 바꾼 효과는 0.75에서 0.72였고, MoE 안에서 multi projection을 single patch 16으로 바꾼 효과는 0.72에서 0.65로 더 컸다. 그런데 dense decoder에 single patch 16만 적용한 구성은 보고하지 않았다. routing centroid를 얻기 위해 single projection dense 모델을 이미 학습했는데도 그 성능은 나와 있지 않다. 원래 Moirai와 비교할 때는 batch 크기(256에서 1,024)와 학습 step 수도 달라서, 개선폭에는 학습 설정 차이도 섞여 있다.
- **PFNSeparability** (조사자 판단) [graph-structure-use, observation-mask] [analyst] 그래프 의존성과 missing features가 있는 우리의 prior에 정리를 그대로 적용할 수 없다.
- **StructuralMissingPFN** (조사자 판단) [graph-structure-use] [analyst] Graph-dependent rows, heterogeneous schemas와 우리의 PCFI/FISF+GraphPFN 비교는 검증하지 않는다.
- **TabImpute** (조사자 판단) [graph-structure-use] [analyst] Imputation 성능이 GraphPFN 분류 개선이나 그래프의 long-range feature 추론을 입증하지 않는다.
- **Wander** (조사자 판단) [graph-structure-use] [analyst] 구조 task에서의 큰 우위와 달리, feature가 있는 실제 node classification에서는 GraphPFN 대비 우위가 평균 1.65점으로 작다. 14개 데이터셋 계열 중 5개(Airports, Wiki filt., Actor, Roman Empire, HM Cat.)에서는 GraphPFN이 앞섰다. 튜닝된 GCN과의 격차도 Roman Empire(79.6 대 65.4)와 HM Cat.(66.4 대 48.7)에서 컸다. 극적인 수치(GRIDS 96.6%)는 long-range 전파가 필요하도록 설계된 synthetic 과제와 feature 없는 그래프에서 나온 것이다.

## 4. 내 연구에서 이미 확인한 것
### 이미 닫은 갈래 — 같은 가설을 이름만 바꿔 반복하는 건 아닌지 확인
- **BIND-F01** (Common-context witness 고정 곱셈) [graph-structure-use] Class pooling 전 context identity를 보존해 곱하면 실제 graph에서 좋아진다.
  - 판정: 고정 common-witness product 중단. k20 pooling-before-product: ACM76.390% vs uniform LP85.555%, IMDB28.311% vs35.413%. IMDB k20 test row 약96.1%는 공통 seed support가0이었다.
  - 닫은 범위: 현재 모든 relation이 같은 context witness를 가져야 하는 고정 곱셈
  - 닫지 않은 것: Task별 variable binding·논리 연산을 추론하는 일반 executor는 별개다.
  - 원인·병목 [진단이 지지]: 동일 witness를 강제하는 곱셈이 현재 sparse-support graph에서 대부분의 evidence를 제거했다. 표현력 collision toy가 실제 오류 원인이라는 증거는 없었다.
  - 재검토 조건: 공유 witness가 필요한 경우와 별개 witness를 허용할 경우를 관측 context로 구분하는 연산이 나올 때.
  - 기준선 / 최소 재검증: Uniform LP, class-pooling 후 product, 같은 graph의 강한 PFN / 먼저 실제 common-support 빈도와 오류의 관계를 확인하고, 고정 곱셈이 아닌 task-adaptive binding의 independent gain을 비교한다.
  - 원문: findings/sources/graphpfn-2026-11-01/binding.md
- **RATIO-F01** (Frozen counterfactual PFN residual) [graph-structure-use] Full−Neutral log probability가 LP에 더할 새로운 feature evidence다.
  - 판정: Frozen 비율 보정 중단. FISF ratio ACM82.35%, IMDB34.45%; LP85.55/35.41%, Full PFN74.36/44.55%. Controlled ratio ACM82.22/IMDB34.50%도 개선하지 못했다.
  - 닫은 범위: 현재 frozen full/neutral 확률 비율의 λ=1 보정
  - 닫지 않은 것: LP-conditioned 학습과 일관된 생성모형의 likelihood ratio 일반은 별개다.
  - 원인·병목 [진단이 지지]: Neutral이 정확한 feature marginalization이 아니므로 비율을 likelihood ratio로 해석할 근거가 없다. IMDB LP log margin은0.134~0.151로 작고, residual argmax 변경률34.68%였다. 원인별 기여는 분리하지 않았다.
  - 재검토 조건: 통제 입력의 의미와 feature marginalization을 정의하고 확률 비율이 유효한 증거가 되는 조건을 제시하는 방법이 나올 때.
  - 기준선 / 최소 재검증: LP/PFN alone, 50:50, controlled neutral / 먼저 feature intervention으로 순효용을 확인하고, 동일 구조·주입 아래 ratio가 정답 방향 보정인지 새 graph에서 평가한다.
  - 원문: findings/sources/graphpfn-2026-11-01/ratio.md; findings/sources/graphpfn-2026-11-01/feature_intervention.md
- **FEAT-F01** (실제 관측 feature 기여의 개입 분석) [graph-structure-use, observation-mask] IMDB의 PFN 우위는 남은 실제 관측 feature의 평균 추가 효용이다.
  - 판정: 해당 feature-reliability 동기 약화. IMDB FISF Full44.55%→No-observed44.51%; controlled Full−Zero0.03%p. 제거 전후 argmax는 평균30.47% 바뀌었으므로 feature가 예측에 무영향이라는 뜻은 아니다.
  - 닫은 범위: 현재 IMDB/99.5% 결과의 PFN−LP 격차를 실제 feature 복원 이득으로 설명
  - 닫지 않은 것: 다른 결측률·graph와 query별 feature utility는 기각하지 않는다.
  - 원인·병목 [진단이 지지]: 평균상 실제 값 효과가 거의 상쇄됐다. 구조 입력 PFN과 synthetic-input 경로의 차이를 feature-only evidence로 오인할 수 없다. Node별 양·음의 효과가 왜 상쇄되는지는 미상이다.
  - 재검토 조건: 실제 관측 feature의 양·음 utility를 누수 없이 분리하거나, 유효 feature가 남는 조건을 특정한 방법이 나올 때.
  - 기준선 / 최소 재검증: Structure-only PFN, no-observed end-to-end, independent-injection controlled Full/Zero / Mask·context·query·graph를 맞춘 제거/셔플 개입에서 실제 값 경로와 synthetic injection 변화를 분리한다.
  - 원문: findings/sources/graphpfn-2026-11-01/feature_intervention.md
- **COUP-F01** (Feature↔Label 양방향 추론) [graph-structure-use, observation-mask] Label→feature 반복 피드백이 일방향 추론보다 유용하다.
  - 판정: 피드백 증분 미확인. Matched 일방향72.72%, 양방향72.66%; 차이−0.06%p CI[−0.50,+0.39]. Shape shift 차이−0.01%p CI[−0.52,+0.55].
  - 닫은 범위: 현재 quadratic coupling을 더 반복·확대하는 방향
  - 닫지 않은 것: 비선형 label-conditioned feature inference와 다른 유효 prior는 평가하지 않았다.
  - 원인·병목 [진단이 지지]: 피드백의 추가 정보를 확보하지 못했다. 관측 feature가 전혀 없으면 latent H가0에 머물고 피드백 제거와 출력이 같았다. 이 구조적 퇴화가 모든 조건의 미개선을 설명하지는 않는다.
  - 재검토 조건: 라벨 피드백이 실제로 새로운 feature 상태를 만들고 그 정보가 일방향 모델에 없음을 보이는 추론 연산이 나올 때.
  - 기준선 / 최소 재검증: 동일 예산 일방향 모델, 피드백 제거, 강한 context ridge baseline / Zero-observation 퇴화와 nonzero 조건을 나눠 같은 초기화·task·예산으로 실제 예측 증분을 비교한다.
  - 원문: findings/sources/graphpfn-2026-11-01/history.md
- **FMARG-F01** (Frozen GraphPFN joint feature-completion marginalization) [graph-structure-use, observation-mask, tokenization] 단일 대치 대신 graph-correlated feature completion의 예측을 평균하면 두 주 결측 조건에서 point/diagonal/zero/PCFI 대조를 모두 넘는다.
  - 판정: 현재 frozen surrogate completion operator의 사전 primary gate 미통과·확대 중단. uniform NLL zero0.92888, PCFI0.93539, mean0.94890, joint0.91589, diagonal0.91596; clustered NLL zero0.93084, PCFI0.93279, mean0.94698, joint0.91352, diagonal0.91743。Joint−Mean: Uniform-0.03301 CI[-0.06064,-0.01167], Clustered-0.03346 CI[-0.06395,-0.00811]。Joint−Diagonal: Uniform-0.00007 CI[-0.00394,+0.00354], Clustered-0.00391 CI[-0.00697,-0.00087]。
  - 닫은 범위: 현재 graph Gaussian surrogate, 고정 zero+mask 학습 PFN, 4 completion·동일 생성 family fresh32 graphs에서 이 연산을 확대해 메인 메소드로 삼는 것
  - 닫지 않은 것: Context labels에 조건화한 feature law, joint predictive training, cross-feature dependency, 정확한 SCM conditional, 실제 graph·unseen schema는 평가하지 않았다. GP likelihood는 공식 SCM posterior가 아니다.
  - 원인·병목 [원인 미상]: 명시한 Gaussian-process surrogate와 4-sample frozen PFN 연산에서 필요한 동시 우위가 없었다. Feature-law misspecification, zero-fill 학습 PFN의 입력 활용 한계, 유한 Monte Carlo, 실제 feature 정보 부족의 원인은 분리하지 못했다.
  - 재검토 조건: 관측된 feature evidence와 graph의 joint missing-feature law를 검증 가능하게 연결하고, point fill 및 같은 예산의 covariance 제거·구조 random-feature 대조를 안정적으로 넘는 추론 연산이 나올 때.
  - 기준선 / 최소 재검증: 동일 PFN의 zero/PCFI/mean/native-NaN·independent sampling·context prior. 후속 positive 주장은 별도의 PCFI/FISF-trained 대조, 비조건부 구조 random features, GCNmf/GSPN/PEMix와의 차별화 필요. / Source·data·예산을 먼저 고정한 새 graph에서 feature conditional의 품질과 predictive marginalization의 증분을 분리한다. Frozen replacement와 distributional-input 재학습을 같은 성과로 세지 않는다.
  - 원문: findings/sources/feature-marginal-2026-11-02/REPORT.md; findings/sources/feature-marginal-2026-11-02/paired.json
- **HET-F01** (Native heterogeneous 입력·기존 relational FM 대조) [graph-structure-use, observation-mask] Adapted HetGFD가 cross-type path 입력보다 큰 증분을 준다.

### 반복된 교훈
- **FMARG-L01** (Frozen GraphPFN joint feature-completion marginalization) [observation-mask] 분포형 input을 적용한 frozen 연산의 성과와 Bayesian posterior·새 학습법을 구분한다.
  - Completion law는 observed-only RMS 좌표의 Gaussian surrogate이며 context labels에는 조건화하지 않는다. PFN은 zero+mask로 학습했던 checkpoint다. PCFI/native-NaN도 같은 checkpoint의 입력 대조이며 각 입력으로 별도 재학습한 모델 성과가 아니다. Point와 sampling 모두 동일4회 PFN forward의 확률을 평균했다.
- **FMARG-L02** (Frozen GraphPFN joint feature-completion marginalization) [graph-structure-use] 노드 간 covariance의 진단은 per-cell variance와 일반 ensemble 효과를 통제한다.
  - Joint와 diagonal에 같은 rho draws·조건부 평균·대각 분산·standard normal draws를 주고 rho 내 off-diagonal covariance만 바꿨다. 두 arm 모두 rho는 graph 공유다. 관측값 clamp·conditional moment node permutation·12000-draw covariance sanity를 확인했다. 이것이 새 정보나 method superiority를 입증하지는 않는다.
- **HET-L01** (Native heterogeneous 입력·기존 relational FM 대조) [context-scale] 기존 relational FM도 현재 node-classification adapter에서는 자동으로 missing에 강하지 않았다.
  - RDB-PFN의 ACM k20 mean_count_depth5 full81.53%/missing66.55%, official_depth2 full74.87%/missing35.18%. RT budget 표는 64-query·1 seed 대조로 제한된다.
- **HET-L02** (Native heterogeneous 입력·기존 relational FM 대조) [observation-mask] 미리 집계된 helper feature를 독립 native 관측값으로 취급하지 않는다.
  - ACM/IMDB helper feature는 target feature에서 파생된 집계일 수 있음을 확인했다. DBLP는 서로 다른 native source block으로 별도 처리했다.
- **JIMP-L01** (Public GraphPFN 내부 대치 상태 갱신) [graph-structure-use, tokenization] Joint imputation의 실행 가능성과 반복 피드백의 예측 가치를 구분한다.
  - 실제 공개 GraphPFN의 feature-pair token 구조를 유지했다. 관측값 clamp, 원래 mask 유지, refiner/encoder gradient, 노드 순열, 동일 Frontend/Interleaved 초기화·파라미터·schedule, frozen weights 보존과 성공 update192회를 검사했다. 이 검사는 구현 연결성을 보여주며 메소드 우수성의 증거는 아니다.
- **JIMP-L03** (Public GraphPFN 내부 대치 상태 갱신) [graph-structure-use] 피드백 제거 intervention은 FP16 수치 순서를 맞춰 해석하고, 별도 재학습 대조와 구분한다.
  - No-feedback 대조의 h+new−old를 h+(new−old)로 묶어 cancellation을 보완하고, 동일 process의 standard와 다시 짝지었다. Full-observed96건의 차이는 정확히0, 별도 process replay의 최대 확률 차이는0.00246981이었다. 보정된 Uniform의 standard−no-feedback NLL은+0.00306 CI[+0.00063,+0.00581]로 feedback이 더 나빴다. Clustered와 k1의 CI는0 포함. 학습·주 예측·checkpoint를 바꾸지 않았다.
- **JR-L01** (초기 JR-PFN과 decoder 표현력) [graph-structure-use, observation-mask] Positive-only diffusion의 구조적 불가능성은 loss로 고칠 수 없었다.
  - Context label이 모두 A일 때 당시 decoder는 모든 query에서 p(A)≥0.5. Exact teacher는 nonedge로 반대 class를 지지할 수 있었다. 이후 contrastive/BP decoder가 이 제한을 넘었다.
- **REOPEN-L01** (실패 기록과 기존 논문을 연결한 후속 후보 선별) [context-scale, graph-structure-use, observation-mask, tokenization, feature memory, label context] 현재 LimiX의 기본 sample attention에서 label-context와 feature-memory의 접근 범위가 묶여 있다.
  - common.py는 context 노드를 앞에 놓고 모든 base layer에 eval_pos=len(context)를 전달한다. Vendor layer.py의 call_sequence_attention은 context와 query 양쪽의 key/value에 x[:, :eval_pos]를 사용한다. 따라서 label이 없는 노드의 관측값을 해당 base attention의 직접 key/value로 읽지는 않는다. Residual의 query 자기 feature와 graph adapter 경로는 존재하므로 '그 관측값을 전혀 사용하지 못한다'는 뜻이 아니다.
- **REOPEN-L02** (실패 기록과 기존 논문을 연결한 후속 후보 선별) [feature memory] 이번 문헌 대조는 기존 gate를 바꾸지 않고 후보와 진단 대조를 구분한다.
  - MCP-P02의 off-diagonal/clustered accuracy +3.43%p는 보존한 미독립 재현 신호이며 원래 NLL gate는 실패 그대로다. Feature memory, walk, 기대 token의 우열은 아직 측정하지 않았다. 기존 논문은 이 3.43%p의 원인이나 LLBP-F11의 Grid6 우위를 뒤집지 않았다.
- **LLBP-L0** (Learned-Likelihood BP / EAJ) [graph-structure-use] Teacher를 정확하게 주는 것과 decoder가 그 target을 표현할 수 있는 것은 다르다.
  - 양의 relation weight와 normalization을 쓰는 label diffusion은 context가 전부 클래스 a이면 모든 query에서 p(a) ≥ 1/2를 유지한다. Nonedge로 반대 클래스를 지지하는 exact SBM teacher를 표현할 수 없었고, 이후 decoder 자체를 바꾸는 방향으로 이동했다.
- **ROLE-L01** (Plain relation adaptation과 CRR 제안 철회) [graph-structure-use] Plain이 전역 relation utility 적응을 못한다는 전제로 새 router를 정당화하지 않는다.
  - 공유 relation MLP에 relation-ID embedding이 없고, context 통계를 따라 역할 교환에 적응했다. Conflict end-to-end는 약2.09%p 하락해 완전 robustness는 아니다.
- **ROLE-L02** (Plain relation adaptation과 CRR 제안 철회) [graph-structure-use] k=1의 centered label-alignment 통계에는 식별 한계가 있다.
  - 클래스당 context 하나면 서로 다른 class centered one-hot 내적은 모두 −1/C다. 이 통계만 복잡하게 인코딩해도 새 정보가 생기지 않는다. 재배선 경로 품질 차이도 함께 고려해야 한다.
- **NEXT-L01** (Random-fill controls 이후의 문헌 기반 후보 선별) [observation-mask] Missing PFN·flow posterior·separable prior·tractable marginalization 자체를 새 발명이라고 제안하지 않는다.
  - StructuralMissingPFN은 incomplete context의 direct prediction과 auxiliary flow posterior를 이미 제시한다. PFNSeparability는 feature SCM과 label SCM을 독립적으로 뽑는 원리도 명시한다. GSPN은 모델 내 missing-variable marginalization을 제공한다. 새로운 적용이나 구현만으로 novelty가 확보되지 않는다.
- **RFILL-L01** (Frozen feature sampling random-fill controls) [observation-mask] 분산 맞춤 null을 완전히 무정보 random baseline이라고 부르지 않는다.
  - Iid/graph-prior variance-matched null에는 원래 conditional variance 정보가 남는다. Unit-noise에는 missing proposal의 관측값 정보가 없지만 실제 관측 위치의 값은 여전히 PFN에 제공한다. Null 우위/동등성을 전체 observed feature의 무용함으로 확대하지 않는다.
- **REG-L01** (Reference-regret prior curriculum) [observation-mask] Singleton observed feature centering은 입력 정보를 없앨 수 있다.
  - Test99.5% whole-node에서 PCFI input 전체가0인 episode는 uniform20/32, clustered32/32. 관측 행0~1개에서 centering 손실을 직접 확인했다.

### 보존한 결과 — 재사용할 수 있는 자산
- **FMARG-P02** (Frozen GraphPFN joint feature-completion marginalization) [observation-mask, tokenization] 여러 completion의 확률 평균은 같은 PFN의 단일 mean 대치와 PCFI 입력보다 낮은 NLL을 얻었다.

### 아직 안 한 것 — 실패로 세지 않음
- **CFB-U01** (Context-conditioned feature belief GraphPFN 설계 검토) [graph-structure-use, observation-mask] Context labels에 조건화한 joint feature law와 shared observed encoder/particle suffix를 학습한 GraphPFN
  - 최종 목표와 loss/계산 공유의 설계만 정리했다. 새 neural model 학습, random-fill null control, label-blind 대비, CE-only 대비 coherence의 독립 이득, latency·memory 및 실제 graph/schema 전이는 아직 실행하지 않았다.
- **REOPEN-U01** (실패 기록과 기존 논문을 연결한 후속 후보 선별) [context-scale, graph-structure-use, observation-mask, tokenization, feature memory, query query attention, observed key value, ephris, tabimpute] Label memory와 observed-feature memory를 분리하는 graph PFN
  - TabImpute의 query 상호작용과 Ephris의 전체 노드 feature Gather를 단서로, label 읽기는 C, feature f의 실측값 읽기는 O_f={j:M_jf=1}로 두는 후보. NEXT-U02의 sparse observation 안을 구체화한 것으로, 별개의 발명·학습된 성공으로 세지 않는다.
- **REOPEN-U02** (실패 기록과 기존 논문을 연결한 후속 후보 선별) [context-scale, graph-structure-use, observation-mask] Missing 영역을 통과하는 경로 자체를 읽는 observation-aware walk PFN
  - Wander는 긴 walk와 feature-free 예측의 기존 실증을 갖는다. 이를 관측 cell이나 context에 이르는 경로 읽기로 확장하는 후보이며, 원래 Wander부터 강한 baseline으로 쓴다. Wander의 label 방문 walk filter 자체를 새 제안으로 삼지 않는다.
